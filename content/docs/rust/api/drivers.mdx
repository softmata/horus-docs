# Driver API

Load hardware driver configurations from `horus.toml` and use them in your nodes.

```rust
use horus::prelude::*;
use horus::drivers;
```

## Overview

The driver system separates **what hardware you have** (config in `horus.toml`) from **how you use it** (code). Today this gives you:

- **Config-driven hardware declarations** in `horus.toml [drivers]`
- **Typed parameter access** via `DriverParams` (port, baudrate, servo IDs, etc.)
- **Local driver registration** via `register_driver!` — your own `Node` implementations loaded from config
- **Package driver dispatch** — third-party driver nodes installed via `horus add`

<Callout type="info">
**Terra integration is in progress.** The typed Terra accessors (`.dynamixel()`, `.rplidar()`, etc.) currently return config parameters only — they do not create hardware connections. For now, use `DriverParams` to read config values and create hardware connections yourself using the appropriate library (e.g., `serialport`, `rppal`, or terra crates directly). When Terra integration lands, the same config will work with zero code changes.
</Callout>

## Three Driver Sources

| Source | Config key | What it does today |
|--------|-----------|-------------------|
| **Local code** | `node = "MyDriver"` | Instantiates your registered `Node` from config params |
| **Registry package** | `package = "crate-name"` | Instantiates a third-party `Node` from config params |
| **Terra HAL** | `terra = "dynamixel"` | Parses config params (hardware connection coming soon) |

## Loading Drivers

### `drivers::load()`

Reads `horus.toml` `[drivers]` section from the current directory (searches up to 10 parents).

```rust
let mut hw = drivers::load()?;
```

### `drivers::load_from(path)`

Load from a specific config file. Useful for testing or multi-robot setups.

```rust
let mut hw = drivers::load_from("tests/test_drivers.toml")?;
```

## Local Drivers (Fully Working)

The recommended pattern today: declare hardware params in config, register your driver struct, and load it at runtime.

### Step 1: Define your driver

```rust
use horus::prelude::*;
use horus::drivers::{DriverParams, register_driver};

struct ConveyorDriver {
    port: String,
    speed: f64,
    publisher: Topic<CmdVel>,
}

impl ConveyorDriver {
    fn from_params(params: &DriverParams) -> Result<Self> {
        let port: String = params.get("port")?;
        let speed: f64 = params.get_or("speed", 1.0);

        Ok(Self {
            port,
            speed,
            publisher: Topic::new("conveyor.velocity")?,
        })
    }
}

impl Node for ConveyorDriver {
    fn name(&self) -> &str { "ConveyorDriver" }

    fn tick(&mut self) {
        self.publisher.send(CmdVel::new(self.speed as f32, 0.0));
    }

    fn enter_safe_state(&mut self) {
        self.publisher.send(CmdVel::new(0.0, 0.0));
    }
}

// Register so [drivers.conveyor] node = "ConveyorDriver" works
register_driver!(ConveyorDriver, ConveyorDriver::from_params);
```

### Step 2: Configure in horus.toml

```toml
[drivers.conveyor]
node = "ConveyorDriver"
port = "/dev/ttyACM0"
speed = 0.5
```

### Step 3: Load and schedule

```rust
fn main() -> Result<()> {
    let mut hw = drivers::load()?;

    let mut scheduler = Scheduler::new().tick_rate(50_u64.hz());
    scheduler.add(hw.local("conveyor")?)
        .order(0)
        .rate(50_u64.hz())
        .build()?;

    scheduler.run()
}
```

`hw.local()` looks up `"ConveyorDriver"` in the compile-time registry and calls `from_params()` with the config values. It returns `Box<dyn Node>` — ready for the scheduler.

## `HardwareSet`

Returned by `drivers::load()`. Provides config access and driver instantiation.

### Factory Accessors

| Method | Config key | Returns |
|--------|-----------|---------|
| `hw.local("name")` | `node = "StructName"` | `Box<dyn Node>` — from `register_driver!` |
| `hw.package("name")` | `package = "crate-name"` | `Box<dyn Node>` — from registry package |
| `hw.node("name")` | any | `Box<dyn Node>` — dispatches based on source type |

`.node()` is a generic accessor that works for all source types:
- **Local** → delegates to `.local()`
- **Package** → delegates to `.package()`
- **Terra** → returns a stub node (use terra config accessors instead)

### Terra Config Accessors

These accessors return a `DriverHandle` containing the parsed config params and the terra driver name. Use them to read hardware configuration from `horus.toml`:

| Method | Config key | Hardware |
|--------|-----------|----------|
| `hw.dynamixel("name")` | `terra = "dynamixel"` | Dynamixel servo bus |
| `hw.rplidar("name")` | `terra = "rplidar"` | RPLiDAR scanner |
| `hw.realsense("name")` | `terra = "realsense"` | Intel RealSense camera |
| `hw.i2c("name")` | `terra = "mpu6050"` etc. | I2C device |
| `hw.serial("name")` | `terra = "vesc"` etc. | Serial/UART port |
| `hw.can("name")` | `terra = "odrive"` etc. | CAN bus |
| `hw.gpio("name")` | `terra = "gpio"` | GPIO pin |
| `hw.pwm("name")` | `terra = "pwm"` | PWM output |
| `hw.usb("name")` | `terra = "usb"` | USB device |
| `hw.webcam("name")` | `terra = "webcam"` | V4L2 camera |
| `hw.input("name")` | `terra = "input"` | Gamepad/joystick |
| `hw.bluetooth("name")` | `terra = "bluetooth"` | BLE device |
| `hw.net("name")` | `terra = "velodyne"` etc. | TCP/UDP device |
| `hw.ethercat("name")` | `terra = "ethercat"` | EtherCAT bus |
| `hw.spi("name")` | `terra = "spi"` | SPI device |
| `hw.adc("name")` | `terra = "adc"` | ADC channel |
| `hw.raw("name")` | any | Escape hatch |

All error with a clear message listing available drivers if the name is not found.

<Callout type="warning">
These accessors return **config params only** — they do not open hardware connections. Create connections yourself using the params. When Terra integration lands, these will return live hardware handles.
</Callout>

**Using terra config accessors today:**

```rust
let handle = hw.dynamixel("arm")?;

// Read config values
let port: String = handle.params().get("port")?;
let baud: u32 = handle.params().get("baudrate")?;
let ids: Vec<u8> = handle.params().get("servo_ids")?;

// Create your own connection using the config
let serial = serialport::new(&port, baud).open()?;
```

### Introspection

| Method | Returns | Description |
|--------|---------|-------------|
| `hw.list()` | `Vec<&str>` | Sorted list of configured driver names |
| `hw.has("name")` | `bool` | Whether a driver is configured |
| `hw.params("name")` | `Option<&DriverParams>` | Config params for a driver |
| `hw.driver_type("name")` | `Option<&DriverType>` | Terra / Package / Local / Legacy |
| `hw.topic_mapping("name")` | `Option<&TopicMapping>` | Topic config for auto-bridging |
| `hw.len()` | `usize` | Number of configured drivers |
| `hw.is_empty()` | `bool` | Whether no drivers are configured |

---

## `DriverHandle`

Wraps a driver's config params and terra name. Pass to your node constructor.

| Method | Returns | Description |
|--------|---------|-------------|
| `handle.params()` | `&DriverParams` | Config params from `[drivers.NAME]` |
| `handle.terra_name()` | `Option<&str>` | Terra shortname (e.g., `"dynamixel"`) |

---

## `DriverParams`

Typed access to config values from a `[drivers.NAME]` table.

| Method | Description |
|--------|-------------|
| `params.get::<T>("key")?` | Required param — errors if missing or wrong type |
| `params.get_or("key", default)` | Optional param — returns default if missing or wrong type |
| `params.has("key")` | Whether a key exists |
| `params.keys()` | Iterator over param names |
| `params.len()` | Number of params |
| `params.is_empty()` | Whether there are no params |
| `params.raw("key")` | Raw `toml::Value` for a key |

### Supported Types

`get::<T>()` supports: `String`, `bool`, `i32`, `i64`, `u32`, `u64`, `u8`, `f32`, `f64`, `Vec<T>` (for any supported `T`).

**Type coercion:** TOML integers convert to floats (`1000` &rarr; `1000.0`). No other cross-type coercion — a string `"42"` will NOT parse as an integer. Use the correct TOML type in your config.

---

## `TopicMapping`

Optional topic configuration for auto-bridging drivers to HORUS topics. Set via `topic`, `topic_state`, `topic_command` fields in `[drivers.NAME]`:

```toml
[drivers.imu]
terra = "mpu6050"
bus = "i2c-1"
topic = "sensors.imu"

[drivers.arm]
terra = "dynamixel"
port = "/dev/ttyUSB0"
topic_state = "arm.joint_states"
topic_command = "arm.joint_commands"
```

| Field | Description |
|-------|-------------|
| `topic` | Sensor data output topic |
| `topic_state` | Joint state output topic |
| `topic_command` | Command input topic |

These fields are **not** included in `DriverParams` — they're bridge configuration. Access via `hw.topic_mapping("name")`:

```rust
if let Some(mapping) = hw.topic_mapping("arm") {
    if let Some(state_topic) = &mapping.topic_state {
        let pub_state: Topic<JointState> = Topic::new(state_topic)?;
    }
}
```

## `register_driver!`

Register a local driver factory so `hw.local("name")` can instantiate it from config.

```rust
register_driver!(MyDriver, MyDriver::from_params);
```

The factory function signature: `fn(&DriverParams) -> Result<Self>`.

The macro uses `.init_array` for compile-time registration — no manual setup needed.

---

## `DriverType`

Identifies where a driver comes from:

```rust
match hw.driver_type("arm") {
    Some(DriverType::Terra(name))   => println!("Terra: {}", name),
    Some(DriverType::Package(pkg))  => println!("Package: {}", pkg),
    Some(DriverType::Local(node))   => println!("Local: {}", node),
    Some(DriverType::Legacy)        => println!("Legacy feature flag"),
    None                            => println!("Not configured"),
}
```

## Complete Example

```toml
# horus.toml
[package]
name = "my-robot"
version = "0.1.0"

[drivers.arm]
terra = "dynamixel"
port = "/dev/ttyUSB0"
baudrate = 1000000
servo_ids = [1, 2, 3, 4, 5, 6]

[drivers.conveyor]
node = "ConveyorDriver"
port = "/dev/ttyACM0"
speed = 0.5
```

```rust
use horus::prelude::*;
use horus::drivers;

fn main() -> Result<()> {
    let mut hw = drivers::load()?;

    let mut sched = Scheduler::new()
        .tick_rate(100_u64.hz());

    // Local driver — fully working, loaded from config
    sched.add(hw.local("conveyor")?)
        .order(0)
        .rate(50_u64.hz())
        .build()?;

    // Terra driver — read config, create your own connection
    if hw.has("arm") {
        let handle = hw.dynamixel("arm")?;
        let port: String = handle.params().get("port")?;
        let baud: u32 = handle.params().get("baudrate")?;
        let ids: Vec<u8> = handle.params().get("servo_ids")?;

        sched.add(ArmDriver::new(&port, baud, ids)?)
            .order(10)
            .rate(500_u64.hz())
            .on_miss(Miss::SafeMode)
            .build()?;
    }

    sched.run()
}
```

## Testing with Mock Config

Use `drivers::load_from()` to load from a test config file:

```rust
#[test]
fn conveyor_from_config() {
    std::fs::write("test_drivers.toml", r#"
        [drivers.conveyor]
        node = "ConveyorDriver"
        port = "/dev/null"
        speed = 0.0
    "#).unwrap();

    let mut hw = drivers::load_from("test_drivers.toml").unwrap();
    let _node = hw.local("conveyor").unwrap();

    std::fs::remove_file("test_drivers.toml").ok();
}
```

## Error Handling

All driver methods return `Result<T>`. Common error conditions:

| Operation | Error | When |
|-----------|-------|------|
| `drivers::load()` | `ConfigError` | No `horus.toml` found (searches up to 10 levels) |
| `hw.dynamixel("name")` | `ConfigError` | Driver not found — error lists available drivers |
| `hw.dynamixel("name")` | `ConfigError` | Wrong source type (e.g., calling `.dynamixel()` on a `package` driver) |
| `hw.local("name")` | `ConfigError` | No factory registered via `register_driver!` |
| `params.get::<T>("key")` | `ConfigError` | Key missing or type mismatch |

```rust
let mut hw = match drivers::load() {
    Ok(hw) => hw,
    Err(e) => {
        hlog!(error, "No hardware config: {}", e);
        hlog!(info, "Running in simulation mode");
        return Ok(());
    }
};

if hw.has("arm") {
    let handle = hw.dynamixel("arm")?;
    hlog!(info, "Arm on {}", handle.params().get_or("port", "/dev/ttyUSB0"));
}
```
