## Node

The fundamental trait for all computation units in HORUS.

```rust
pub trait Node: Send {
    // Required
    fn name(&self) -> &'static str;
    fn tick(&mut self);

    // Optional lifecycle
    fn init(&mut self) -> Result<()> { Ok(()) }
    fn shutdown(&mut self) -> Result<()> { Ok(()) }
    fn on_error(&mut self, error: &str) { hlog!(error, "Node error: {}", error); }

    // Optional metadata
    fn publishers(&self) -> Vec<TopicMetadata> { Vec::new() }
    fn subscribers(&self) -> Vec<TopicMetadata> { Vec::new() }
    fn priority(&self) -> u32 { 50 }
    fn rate_hz(&self) -> Option<f64> { None }
    fn config(&self) -> NodeConfig { NodeConfig::default() }
    fn is_healthy(&self) -> bool { true }

    // Optional checkpoint/restore
    fn checkpoint_state(&self) -> Option<Vec<u8>> { None }
    fn restore_state(&mut self, data: &[u8]) -> Result<()> { Ok(()) }
    fn supports_checkpointing(&self) -> bool { false }
}
```

### Required Methods

#### `name`

```rust
fn name(&self) -> &'static str
```

Returns the unique identifier for this node. Must be a static string.

**Returns:** `&'static str` - The node's name

**Example:**
```rust
fn name(&self) -> &'static str {
    "my_sensor_node"
}
```

---

#### `tick`

```rust
fn tick(&mut self)
```

Called repeatedly by the scheduler. This is the main execution loop for the node.

**Example:**
```rust
fn tick(&mut self) {
    // Read sensor
    let value = self.sensor.read();

    // Publish data
    self.publisher.send(value);

    // Log using hlog! macro
    hlog!(debug, "Published: {}", value);
}
```

---

### Optional Methods

#### `init`

```rust
fn init(&mut self) -> Result<()>
```

Called once before the first tick. Use for initialization that may fail.

**Returns:** `Result<()>` - Ok on success, Err on failure

**Default:** Returns `Ok(())`

---

#### `shutdown`

```rust
fn shutdown(&mut self) -> Result<()>
```

Called when the scheduler is stopping. Use for cleanup.

**Returns:** `Result<()>` - Ok on success, Err on failure

**Default:** Returns `Ok(())`

---

#### `on_error`

```rust
fn on_error(&mut self, error: &str)
```

Called when an error occurs during tick execution.

**Parameters:**
- `error` - Error message string

**Default:** Logs the error using `hlog!`

---

#### `rate_hz`

```rust
fn rate_hz(&self) -> Option<f64>
```

Returns the node's desired tick rate in Hz. Overrides the scheduler's global rate for this node.

**Returns:** `Option<f64>` - Some(hz) for a custom rate, None for the scheduler default

**Default:** Returns `None`

**Example:**
```rust
fn rate_hz(&self) -> Option<f64> {
    Some(100.0) // Run at 100 Hz
}
```

#### `publishers`

```rust
fn publishers(&self) -> Vec<TopicMetadata>
```

Returns the list of topics this node publishes to. Override this if your node publishes to topics — the default returns empty, which may hide connectivity issues during debugging.

**Returns:** `Vec<TopicMetadata>`

**Default:** Returns empty `Vec`

---

#### `subscribers`

```rust
fn subscribers(&self) -> Vec<TopicMetadata>
```

Returns the list of topics this node subscribes to. Override this if your node subscribes to topics.

**Returns:** `Vec<TopicMetadata>`

**Default:** Returns empty `Vec`

---

#### `priority`

```rust
fn priority(&self) -> u32
```

Returns the node's execution priority. Lower numbers = higher priority.

**Returns:** `u32` - Priority level (default: 50)

**Default:** Returns `50` (normal priority)

---

#### `config`

```rust
fn config(&self) -> NodeConfig
```

Returns the node's configuration (restart policy, timeouts, etc.).

**Returns:** `NodeConfig`

**Default:** Returns `NodeConfig::default()`

---

#### `is_healthy`

```rust
fn is_healthy(&self) -> bool
```

Health check for the node. Override this for production nodes to report actual health status. The default always returns `true`, which may mask real issues.

**Returns:** `bool`

**Default:** Returns `true`

---

#### `checkpoint_state`

```rust
fn checkpoint_state(&self) -> Option<Vec<u8>>
```

Serializes node state for checkpointing. Override to save internal state during checkpoints.

**Returns:** `Option<Vec<u8>>` - `Some(bytes)` with serialized state, or `None` if no state to checkpoint

**Default:** Returns `None`

---

#### `restore_state`

```rust
fn restore_state(&mut self, data: &[u8]) -> Result<()>
```

Restores node state from a checkpoint. Called during recovery after a crash.

**Parameters:**
- `data` - Serialized state previously returned by `checkpoint_state()`

**Returns:** `Result<()>`

**Default:** Returns `Ok(())`

---

#### `supports_checkpointing`

```rust
fn supports_checkpointing(&self) -> bool
```

Returns whether this node supports checkpointing. Used by the scheduler to determine which nodes need state persistence.

**Returns:** `bool`

**Default:** Returns `false`

### Example Implementation

```rust
use horus::prelude::*;

struct TemperatureSensor {
    publisher: Topic<f32>,
    sample_count: u64,
}

impl TemperatureSensor {
    pub fn new() -> Result<Self> {
        Ok(Self {
            publisher: Topic::new("temperature")?,
            sample_count: 0,
        })
    }
}

impl Node for TemperatureSensor {
    fn name(&self) -> &'static str {
        "temperature_sensor"
    }

    fn init(&mut self) -> Result<()> {
        hlog!(info, "Temperature sensor initialized");
        Ok(())
    }

    fn tick(&mut self) {
        // Simulate reading temperature
        let temp = 20.0 + (self.sample_count as f32 * 0.1).sin() * 5.0;

        self.publisher.send(temp);
        self.sample_count += 1;
    }

    fn shutdown(&mut self) -> Result<()> {
        hlog!(info, "Sensor shutdown after {} samples", self.sample_count);
        Ok(())
    }
}
```

## Topic

Unified typed pub/sub channel with automatic backend selection. Topic auto-selects the optimal IPC backend based on message type and usage patterns.

```rust
pub struct Topic<T> { /* fields omitted */ }
```

### Type Parameters

- `T` - Message type. Must implement: `Clone + Send + Sync + Serialize + DeserializeOwned + 'static`

### Backend Selection

Topic automatically selects the fastest backend for your use case:

| Backend | Latency | Use Case |
|---------|---------|----------|
| DirectChannel | ~3-5ns | Same-thread only |
| SpscIntra | ~18ns | In-process, 1 producer + 1 consumer |
| MpscIntra | ~26ns | In-process, many producers + 1 consumer |
| SpmcIntra | ~40ns | In-process, 1 producer + many consumers |
| MpmcIntra | ~80ns | In-process, many-to-many |
| PodShm | ~50ns | Cross-process, POD types (zero-copy) |
| SpscShm | ~85ns | Cross-process, 1:1 |
| MpscShm | ~65ns | Cross-process, many:1 |
| SpmcShm | ~70ns | Cross-process, 1:many |
| MpmcShm | ~167ns | Cross-process, many:many |
| Network | varies | UDP/Unix socket/Zenoh |

### Constructors

#### `new`

```rust
pub fn new(name: impl Into<String>) -> Result<Self>
```

Creates a new Topic with automatic backend selection and auto-sized capacity. Capacity is auto-calculated based on message size (one 4KB page of slots, clamped to 16-1024).

Parses the topic name/endpoint to select the appropriate backend:
- `"topic"` → Local shared memory (MpmcShm)
- `"topic@host:port"` → Network backend
- `"topic@zenoh"` → Zenoh transport

**Parameters:**
- `name` - Topic name or endpoint string

**Returns:** `Result<Topic<T>>`

**Example:**
```rust
let topic: Topic<f32> = Topic::new("sensor.temperature")?;
let net_topic: Topic<f32> = Topic::new("sensor@192.168.1.5")?;
```

---

#### `with_capacity`

```rust
pub fn with_capacity(name: impl Into<String>, capacity: usize) -> Result<Self>
```

Creates a Topic with explicit buffer capacity.

**Parameters:**
- `name` - Topic name or endpoint string
- `capacity` - Ring buffer capacity (must be power of 2 for ring backends)

**Returns:** `Result<Topic<T>>`

**Example:**
```rust
let topic: Topic<Image> = Topic::with_capacity("camera.image", 16)?;
```

#### `publish`

```rust

```

Creates a topic from a type-safe descriptor (publishing side). Use with the `topics!` macro for compile-time checked topic names.

**Example:**
```rust

    CMD_VEL: CmdVel = "cmd_vel",
}

let publisher = Topic::publish(CMD_VEL)?;
publisher.send(CmdVel { linear: 1.0, angular: 0.0 });
```

---

#### `subscribe`

```rust
pub fn subscribe(descriptor: TopicDescriptor<T>) -> Result<Self>
```

Creates a topic from a type-safe descriptor (subscribing side).

**Example:**
```rust
topics! {
    SENSOR_DATA: f64 = "sensor_data",
}

let sub = Topic::subscribe(SENSOR_DATA)?;
if let Some(value) = sub.recv() { /* ... */ }
```

---

#### `from_config_named`

```rust
pub fn from_config_named(topic_name: &str) -> Result<Self>
```

Creates a Topic from configuration file (`horus.toml` or `horus.yaml`).

**Config search paths:**
1. `./horus.toml` or `./horus.yaml`
2. `~/.horus/config.toml` or `~/.horus/config.yaml`
3. `/etc/horus/config.toml` or `/etc/horus/config.yaml`

```rust

```

### Methods

#### `with_logging`

```rust
pub fn with_logging(self) -> Self
```

Enables logging and metrics collection on this topic. When enabled, every `send()` and `recv()` call automatically records metrics and logs message summaries. Requires `T: LogSummary`.

**Returns:** `Self` - The topic with logging enabled

**Example:**
```rust
// Default: zero-overhead, no logging
let fast_topic: Topic<f32> = Topic::new("sensor.temperature")?;

// With logging: automatic metrics + message summaries
let logged_topic: Topic<f32> = Topic::new("sensor.temperature")?.with_logging();
```

---

#### `send`

```rust
pub fn send(&self, msg: T)
```

Sends a message to the topic. Non-blocking, infallible. Uses ring buffer "keep last" semantics — oldest message overwritten when buffer is full.

If `.with_logging()` was called, metrics and message summaries are automatically recorded. Otherwise, zero-overhead.

**Parameters:**
- `msg` - Message to send

**Example:**
```rust
self.publisher.send(42.0);
```

---

#### `recv`

```rust
pub fn recv(&self) -> Option<T>
```

Receives the latest message from the topic. Non-blocking.

**Returns:** `Option<T>` - Some(message) if available, None otherwise

**Example:**
```rust
if let Some(value) = self.subscriber.recv() {
    // Process value
}
```

---

#### `has_messages`

```rust
pub fn has_messages(&self) -> bool
```

Checks if messages are available without consuming them.

**Returns:** `bool`

---

#### `name`

```rust
pub fn name(&self) -> &str
```

Returns the topic name.

**Returns:** `&str`

---

#### `metrics`

```rust
pub fn metrics(&self) -> TopicMetrics
```

Returns current metrics snapshot (sent/received counts, failure counts).

**Returns:** `TopicMetrics`

---

#### `connection_state`

```rust
pub fn connection_state(&self) -> ConnectionState
```

Returns current connection state. Always `Connected` for local shared memory backends; reflects actual status for network backends.

**Returns:** `ConnectionState`

---

#### `backend_type`

```rust
pub fn backend_type(&self) -> &'static str
```

Returns the active backend name (for debugging). Examples: `"DirectChannel"`, `"SpscIntra"`, `"MpmcShm"`, `"Network"`.

### Network Endpoints

Topic supports network communication via endpoint syntax in the topic name:

```rust
// Local shared memory (default, fastest)
Topic::new("topic")?;

// Direct TCP connection
Topic::new("topic@192.168.1.100")?;
Topic::new("topic@192.168.1.100:9000")?;

// Multicast discovery
Topic::new("topic@*")?;
```

## TopicConfig

Builder for advanced Topic configuration. Use when you need explicit control over backend selection, access patterns, or process topology.

```rust
pub struct TopicConfig {
    pub name: String,
    pub capacity: u32,
    pub create: bool,
    pub is_producer: bool,
    pub access_pattern: AccessPattern,
    pub topology: ProcessTopology,
    pub backend_hint: BackendHint,
}
```

### Builder Methods

```rust
TopicConfig::new("sensor_data")
    .with_capacity(256)
    .as_producer()              // or .as_consumer()
    .with_access_pattern(AccessPattern::Spsc)
    .with_topology(ProcessTopology::CrossProcess)
    .with_backend(BackendHint::Auto)   // or force a specific backend
    .same_thread()              // convenience: SameThread + Spsc
    .same_process()             // convenience: SameProcess topology
    .cross_process()            // convenience: CrossProcess topology
    .spsc()                     // convenience: Spsc pattern
    .mpmc()                     // convenience: Mpmc pattern
```

### AccessPattern

```rust
pub enum AccessPattern {
    Spsc,   // Single Producer, Single Consumer
    Spmc,   // Single Producer, Multiple Consumers
    Mpsc,   // Multiple Producers, Single Consumer
    Mpmc,   // Multiple Producers, Multiple Consumers (default)
}
```

### ProcessTopology

```rust
pub enum ProcessTopology {
    SameThread,    // Fastest path (~3-5ns)
    SameProcess,   // Different threads (~25-80ns)
    CrossProcess,  // Via shared memory (~50-167ns, default)
}
```

### BackendHint

```rust
pub enum BackendHint {
    Auto,            // Automatic selection (default)
    DirectChannel,   // Same-thread only (~3-5ns)
    SpscIntra,       // Same-process SPSC (~25ns)
    SpscShm,         // Cross-process SPSC (~85ns)
    PodShm,          // Cross-process POD (~50ns)
    MpmcShm,         // Cross-process MPMC (~167ns)
    MpscIntra,       // Same-process MPSC (~35ns)
    SpmcIntra,       // Same-process SPMC (~40ns)
    MpmcIntra,       // Same-process MPMC (~80ns)
    MpscShm,         // Cross-process MPSC (~65ns)
    SpmcShm,         // Cross-process SPMC (~70ns)
    Network,         // UDP/Unix socket/Zenoh
    NetworkZenoh,    // Zenoh transport
}
```

### Node Management

#### `add`

```rust
pub fn add<N: Node + 'static>(&mut self, node: N) -> NodeBuilder<'_>
```

Adds a node using the fluent builder API. Returns a `NodeBuilder` for configuring the node.

**Returns:** `NodeBuilder` for chaining configuration

**NodeBuilder Methods:**
- `.order(priority)` - Set execution priority (0 = highest)
- `.tier(NodeTier::*)` - Set explicit execution tier
- `.rate_hz(freq)` - Set custom tick rate
- `.rt()` - Mark as real-time node
- `.done()` - Finalize and add the node

**NodeTier Options:**
- `NodeTier::UltraFast` - Ultra-fast (&lt;1μs), inline execution
- `NodeTier::Fast` - Fast (&lt;10μs), inline execution
- `NodeTier::Normal` - Standard (&lt;100μs)
- `NodeTier::AsyncIO` - Non-blocking I/O
- `NodeTier::Background` - Low-priority (&gt;100μs)
- `NodeTier::Isolated` - Process isolation

**Example:**
```rust
use horus::prelude::*;

scheduler.add(pid_controller).order(0).tier(NodeTier::UltraFast).done();
scheduler.add(sensor_reader).order(1).tier(NodeTier::Fast).done();
scheduler.add(cloud_sync).order(5).tier(NodeTier::AsyncIO).done();
scheduler.add(data_logger).order(10).tier(NodeTier::Background).done();
```

fn main() -> Result<()> {
