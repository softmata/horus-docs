The core runtime crate for the HORUS robotics framework. Provides the fundamental building blocks for creating distributed real-time robotics systems.

## Node

The fundamental trait for all computation units in HORUS.

```rust
pub trait Node: Send {
    fn name(&self) -> &'static str;
    fn tick(&mut self);

    // Optional methods with defaults
    fn init(&mut self) -> Result<()> { Ok(()) }
    fn shutdown(&mut self) -> Result<()> { Ok(()) }
    fn on_error(&mut self, error: &str) { }
    fn rate_hz(&self) -> Option<f64> { None }
    fn get_publishers(&self) -> Vec<TopicMetadata> { vec![] }
    fn get_subscribers(&self) -> Vec<TopicMetadata> { vec![] }
}
```

### Required Methods

#### `name`

```rust
fn name(&self) -> &'static str
```

Returns the unique identifier for this node. Must be a static string.

**Returns:** `&'static str` - The node's name

**Example:**
```rust
fn name(&self) -> &'static str {
    "my_sensor_node"
}
```

---

#### `tick`

```rust
fn tick(&mut self)
```

Called repeatedly by the scheduler. This is the main execution loop for the node.

**Example:**
```rust
fn tick(&mut self) {
    // Read sensor
    let value = self.sensor.read();

    // Publish data
    self.publisher.send(value);

    // Log using hlog! macro
    hlog!(debug, "Published: {}", value);
}
```

---

### Optional Methods

#### `init`

```rust
fn init(&mut self) -> Result<()>
```

Called once before the first tick. Use for initialization that may fail.

**Returns:** `Result<()>` - Ok on success, Err on failure

**Default:** Returns `Ok(())`

---

#### `shutdown`

```rust
fn shutdown(&mut self) -> Result<()>
```

Called when the scheduler is stopping. Use for cleanup.

**Returns:** `Result<()>` - Ok on success, Err on failure

**Default:** Returns `Ok(())`

---

#### `on_error`

```rust
fn on_error(&mut self, error: &str)
```

Called when an error occurs during tick execution.

**Parameters:**
- `error` - Error message string

**Default:** Logs the error using `hlog!`

---

#### `rate_hz`

```rust
fn rate_hz(&self) -> Option<f64>
```

Returns the node's desired tick rate in Hz. Overrides the scheduler's global rate for this node.

**Returns:** `Option<f64>` - Some(hz) for a custom rate, None for the scheduler default

**Default:** Returns `None`

**Example:**
```rust
fn rate_hz(&self) -> Option<f64> {
    Some(100.0) // Run at 100 Hz
}
```

---

### Example Implementation

```rust
use horus::prelude::*;

struct TemperatureSensor {
    publisher: Topic<f32>,
    sample_count: u64,
}

impl TemperatureSensor {
    pub fn new() -> Result<Self> {
        Ok(Self {
            publisher: Topic::new("temperature")?,
            sample_count: 0,
        })
    }
}

impl Node for TemperatureSensor {
    fn name(&self) -> &'static str {
        "temperature_sensor"
    }

    fn init(&mut self) -> Result<()> {
        hlog!(info, "Temperature sensor initialized");
        Ok(())
    }

    fn tick(&mut self) {
        // Simulate reading temperature
        let temp = 20.0 + (self.sample_count as f32 * 0.1).sin() * 5.0;

        self.publisher.send(temp);
        self.sample_count += 1;
    }

    fn shutdown(&mut self) -> Result<()> {
        hlog!(info, "Sensor shutdown after {} samples", self.sample_count);
        Ok(())
    }
}
```

**Parameters:**

```rust

```

---

### Methods

#### `with_logging`

```rust
pub fn with_logging(self) -> Self
```

Enables logging and metrics collection on this topic. When enabled, every `send()` and `recv()` call automatically records metrics and logs message summaries. Requires `T: LogSummary`.

This is a builder method that returns the topic, so it can be chained with construction.

**Returns:** `Self` - The topic with logging enabled

**Example:**
```rust
// Default: zero-overhead, no logging
let fast_topic: Topic<f32> = Topic::new("sensor.temperature")?;

// With logging: automatic metrics + message summaries
let logged_topic: Topic<f32> = Topic::new("sensor.temperature")?.with_logging();
```

---

#### `send`

```rust
pub fn send(&self, msg: T)
```

Sends a message to the topic. Non-blocking, infallible, ~200ns latency.

If `.with_logging()` was called on this topic, metrics and message summaries are automatically recorded. Otherwise, this is a zero-overhead operation. Uses ring buffer "keep last" semantics — oldest message overwritten when buffer is full.

**Parameters:**
- `msg` - Message to send

**Example:**
```rust
self.publisher.send(42.0);
```

---

#### `recv`

```rust
pub fn recv(&self) -> Option<T>
```

Receives the latest message from the topic. Non-blocking.

If `.with_logging()` was called on this topic, metrics and message summaries are automatically recorded. Otherwise, this is a zero-overhead operation.

**Returns:** `Option\<T\>` - Some(message) if available, None otherwise

**Example:**
```rust
if let Some(value) = self.subscriber.recv() {
    // Process value
}
```

---

#### `get_topic_name`

```rust
pub fn get_topic_name(&self) -> &str
```

Returns the topic name.

**Returns:** `&str`

---

#### `get_metrics`

```rust
pub fn get_metrics(&self) -> TopicMetrics
```

Returns current metrics snapshot.

**Returns:** `TopicMetrics`

---

#### `get_connection_state`

```rust
pub fn get_connection_state(&self) -> ConnectionState
```

Returns current connection state.

**Returns:** `ConnectionState`

### Network Endpoints

Topic supports network communication via endpoint syntax in the topic name:

```rust
// Local shared memory (default, fastest)
Topic::new("topic")?;

// Direct TCP connection
Topic::new("topic@192.168.1.100")?;
Topic::new("topic@192.168.1.100:9000")?;

// Multicast discovery
Topic::new("topic@*")?;
```

## Scheduler

Central orchestrator for node execution with priority-based scheduling. **Deterministic by default.**

```rust
pub struct Scheduler { /* fields omitted */ }
```

### Constructors

#### `new`

```rust
pub fn new() -> Self
```

Creates a **deterministic** scheduler with default settings (~60 Hz tick rate). No learning phase, predictable execution from tick 0.

**Returns:** `Scheduler`

**Example:**
```rust
// Default: deterministic, no learning phase
let scheduler = Scheduler::new();
```

---

### Builder Methods

#### `with_name`

```rust
pub fn with_name(self, name: &str) -> Self
```

Sets the scheduler name.

---

#### `with_capacity`

```rust
pub fn with_capacity(self, capacity: usize) -> Self
```

Pre-allocates capacity for nodes (prevents runtime allocations).

---

#### `with_config`

```rust
pub fn with_config(self, config: SchedulerConfig) -> Self
```

Applies a configuration preset.

**Available Presets:**
- `SchedulerConfig::standard()` - General development
- `SchedulerConfig::hard_realtime()` - &lt;20μs jitter
- `SchedulerConfig::safety_critical()` - Redundancy and monitoring
- `SchedulerConfig::high_performance()` - Maximum throughput

---

#### `enable_determinism`

```rust
pub fn enable_determinism(self) -> Self
```

Explicitly enables deterministic execution mode. Same as default, but more explicit for code clarity.

---

#### `enable_learning`

```rust
pub fn enable_learning(self) -> Self
```

**WARNING: Makes execution non-deterministic!**

Enables the ~100-tick learning phase for automatic node tier classification. Use only when adaptive optimization is worth the non-determinism.

**Example:**
```rust
// Opt-in to non-deterministic learning
let scheduler = Scheduler::new()
    .enable_learning();  // WARNING: Non-deterministic!
```

#### `with_safety_monitor`

```rust

```

Enables safety monitoring with deadline miss threshold.

### Node Management

#### `add`

```rust
pub fn add<N: Node + 'static>(&mut self, node: N) -> NodeBuilder<'_>
```

Adds a node using the fluent builder API. Returns a `NodeBuilder` for configuring the node.

**Returns:** `NodeBuilder` for chaining configuration

**NodeBuilder Methods:**
- `.order(priority)` - Set execution priority (0 = highest)
- `.tier(NodeTier::*)` - Set explicit execution tier
- `.rate_hz(freq)` - Set custom tick rate
- `.rt()` - Mark as real-time node
- `.done()` - Finalize and add the node

**NodeTier Options:**
- `NodeTier::UltraFast` - Ultra-fast (&lt;1μs), inline execution
- `NodeTier::Fast` - Fast (&lt;10μs), inline execution
- `NodeTier::Normal` - Standard (&lt;100μs)
- `NodeTier::AsyncIO` - Non-blocking I/O
- `NodeTier::Background` - Low-priority (&gt;100μs)
- `NodeTier::Isolated` - Process isolation

**Example:**
```rust
use horus::prelude::*;

scheduler.add(pid_controller).order(0).tier(NodeTier::UltraFast).done();
scheduler.add(sensor_reader).order(1).tier(NodeTier::Fast).done();
scheduler.add(cloud_sync).order(5).tier(NodeTier::AsyncIO).done();
scheduler.add(data_logger).order(10).tier(NodeTier::Background).done();
```

---

#### `set_node_rate`

```rust
pub fn set_node_rate(&mut self, name: &str, rate_hz: f64) -> &mut Self
```

Sets per-node tick rate in Hz.

**Example:**
```rust

    .set_node_rate("slow_logger", 1.0);    // 1 Hz
```

### Example

```rust
use horus::prelude::*;
use std::time::Duration;

fn main() -> Result<()> {
    let mut scheduler = Scheduler::new();

    // Add nodes with priorities using fluent API
    scheduler.add(EmergencyStop::new()?).order(0).done();
    scheduler.add(MotorController::new()?).order(1).rate_hz(1000.0).done();
    scheduler.add(SensorTopic::new()?).order(2).done();
    scheduler.add(DataLogger::new()?).order(100).rate_hz(10.0).done();

    // Run for 60 seconds
    scheduler.run_for(Duration::from_secs(60))?;

    Ok(())
}
```

## hlog! Macro

The `hlog!` macro provides structured logging for nodes. Use it instead of println or other logging methods.

```rust
hlog!(level, "message", args...);
```

### Log Levels

```rust
hlog!(trace, "Detailed trace info");
hlog!(debug, "Debug information: {}", value);
hlog!(info, "Node initialized");
hlog!(warn, "Potential issue: {}", issue);
hlog!(error, "Error occurred: {}", err);
```

### Example

```rust
fn tick(&mut self) {
    self.publisher.send(data);
    hlog!(debug, "Published data: {:?}", data);
}

fn init(&mut self) -> Result<()> {
    hlog!(info, "Sensor initialized");
    Ok(())
}
```

## Error (HorusError)

Unified error type for all HORUS operations. The prelude exports `Error` as a short alias for `HorusError`.

```rust
use horus::prelude::*;  // Imports Error, Result

// Error is an alias for HorusError
#[derive(Debug, Error)]
pub enum Error {
    Io(std::io::Error),
    Config(String),
    Backend { backend: String, message: String },
    Communication(String),
    Node { node: String, message: String },
    Driver(String),
    Scheduling(String),
    Memory(String),
    SharedMemory(String),
    Parameter(String),
    Serialization(String),
    Timeout(String),
    NotFound(String),
    PermissionDenied(String),
    InvalidInput(String),
    InitializationFailed(String),
    AlreadyExists(String),
    ParseError(String),
    CommandFailed(String),
    FeatureNotAvailable(String),
    Unsupported(String),
    Internal { message: String, file: &'static str, line: u32 },
    Contextual { message: String, source: Box<dyn Error + Send + Sync> },
}
```

### Factory Methods

```rust
impl Error {
    pub fn config<S: Into<String>>(msg: S) -> Self;
    pub fn backend<S, T>(backend: S, message: T) -> Self;
    pub fn node<S, T>(node: S, message: T) -> Self;
    pub fn communication<S: Into<String>>(msg: S) -> Self;
    pub fn memory<S: Into<String>>(msg: S) -> Self;
    pub fn not_found<S: Into<String>>(resource: S) -> Self;
    pub fn invalid_input<S: Into<String>>(msg: S) -> Self;
}
```

### Predicates

```rust
impl Error {
    pub fn is_not_found(&self) -> bool;
    pub fn is_timeout(&self) -> bool;
    pub fn is_permission_denied(&self) -> bool;
}
```

## Result (HorusResult)

Type alias for Results using Error. The prelude exports `Result\<T\>` as a short alias.

```rust
use horus::prelude::*;

// Result<T> is an alias for std::result::Result<T, Error>
pub type Result<T> = std::result::Result<T, Error>;

// HorusResult<T> still works for backward compatibility
pub type HorusResult<T> = Result<T>;
```

## Performance

| Operation | Latency | Notes |
|-----------|---------|-------|
| `Topic::send()` | **87ns** | Wait-free SPSC |
| `Topic::recv()` | ~175ns | Wait-free SPSC |
| `Topic::send_recv()` | ~262ns | Round-trip |
| `Topic::send()` | **313ns** | Lock-free MPMC |
| `Topic::recv()` | ~313ns | Lock-free MPMC |

**Note:** Topic SPSC is 72% faster than Topic MPMC for single-producer/single-consumer scenarios. Use Topic SPSC for control loops, Topic for multi-subscriber topics.
