The core runtime crate for the HORUS robotics framework. Provides the fundamental building blocks for creating distributed real-time robotics systems.

## Node

The fundamental trait for all computation units in HORUS.

```rust
pub trait Node: Send {
    // Required
    fn tick(&mut self);

    // Name (defaults to struct type name, e.g. `MotorController`)
    fn name(&self) -> &str { /* derived from type name */ }

    // Optional lifecycle
    fn init(&mut self) -> Result<()> { Ok(()) }
    fn shutdown(&mut self) -> Result<()> { Ok(()) }
    fn on_error(&mut self, error: &str) { hlog!(error, "Node error: {}", error); }

    // Optional metadata
    fn publishers(&self) -> Vec<TopicMetadata> { Vec::new() }
    fn subscribers(&self) -> Vec<TopicMetadata> { Vec::new() }
    fn rate_hz(&self) -> Option<f64> { None }
    fn is_healthy(&self) -> bool { true }

    // Optional checkpoint/restore
    fn checkpoint_state(&self) -> Option<Vec<u8>> { None }
    fn restore_state(&mut self, _data: &[u8]) -> Result<()> { Ok(()) }
    fn supports_checkpointing(&self) -> bool { false }
}
```

### Required Methods

#### `tick`

```rust
fn tick(&mut self)
```

Called repeatedly by the scheduler. This is the main execution loop for the node.

**Example:**
```rust
fn tick(&mut self) {
    // Read sensor
    let value = self.sensor.read();

    // Publish data
    self.publisher.send(value);

    // Log using hlog! macro
    hlog!(debug, "Published: {}", value);
}
```

### Optional Methods

#### `init`

```rust
fn init(&mut self) -> Result<()>
```

Called once before the first tick. Use for initialization that may fail.

**Returns:** `Result<()>` - Ok on success, Err on failure

**Default:** Returns `Ok(())`

---

#### `shutdown`

```rust
fn shutdown(&mut self) -> Result<()>
```

Called when the scheduler is stopping. Use for cleanup.

**Returns:** `Result<()>` - Ok on success, Err on failure

**Default:** Returns `Ok(())`

---

#### `on_error`

```rust
fn on_error(&mut self, error: &str)
```

Called when an error occurs during tick execution.

**Parameters:**
- `error` - Error message string

**Default:** Logs the error using `hlog!`

---

#### `rate_hz`

```rust
fn rate_hz(&self) -> Option<f64>
```

Returns the node's desired tick rate in Hz. Overrides the scheduler's global rate for this node.

**Returns:** `Option<f64>` - Some(hz) for a custom rate, None for the scheduler default

**Default:** Returns `None`

**Example:**
```rust
fn rate_hz(&self) -> Option<f64> {
    Some(100.0) // Run at 100 Hz
}
```

---

#### `publishers`

```rust
fn publishers(&self) -> Vec<TopicMetadata>
```

Returns the list of topics this node publishes to. Override this if your node publishes to topics — the default returns empty, which may hide connectivity issues during debugging.

**Returns:** `Vec<TopicMetadata>`

**Default:** Returns empty `Vec`

---

#### `subscribers`

```rust
fn subscribers(&self) -> Vec<TopicMetadata>
```

Returns the list of topics this node subscribes to. Override this if your node subscribes to topics.

**Returns:** `Vec<TopicMetadata>`

**Default:** Returns empty `Vec`

---

#### `is_healthy`

```rust
fn is_healthy(&self) -> bool
```

Health check for the node. Override this for production nodes to report actual health status. The default always returns `true`, which may mask real issues.

**Returns:** `bool`

**Default:** Returns `true`

---

#### `checkpoint_state`

```rust
fn checkpoint_state(&self) -> Option<Vec<u8>>
```

Serializes node state for checkpointing. Override to save internal state during checkpoints.

**Returns:** `Option<Vec<u8>>` - `Some(bytes)` with serialized state, or `None` if no state to checkpoint

**Default:** Returns `None`

---

#### `restore_state`

```rust
fn restore_state(&mut self, data: &[u8]) -> Result<()>
```

Restores node state from a checkpoint. Called during recovery after a crash.

**Parameters:**
- `data` - Serialized state previously returned by `checkpoint_state()`

**Returns:** `Result<()>`

**Default:** Returns `Ok(())`

---

#### `supports_checkpointing`

```rust
fn supports_checkpointing(&self) -> bool
```

Returns whether this node supports checkpointing. Used by the scheduler to determine which nodes need state persistence.

**Returns:** `bool`

**Default:** Returns `false`

### Example Implementation

```rust
use horus::prelude::*;

struct TemperatureSensor {
    publisher: Topic<f32>,
    sample_count: u64,
}

impl TemperatureSensor {
    pub fn new() -> Result<Self> {
        Ok(Self {
            publisher: Topic::new("temperature")?,
            sample_count: 0,
        })
    }
}

impl Node for TemperatureSensor {
    fn name(&self) -> &str {
        "temperature_sensor"
    }

    fn init(&mut self) -> Result<()> {
        hlog!(info, "Temperature sensor initialized");
        Ok(())
    }

    fn tick(&mut self) {
        // Simulate reading temperature
        let temp = 20.0 + (self.sample_count as f32 * 0.1).sin() * 5.0;

        self.publisher.send(temp);
        self.sample_count += 1;
    }

    fn shutdown(&mut self) -> Result<()> {
        hlog!(info, "Sensor shutdown after {} samples", self.sample_count);
        Ok(())
    }
}
```

## Topic

Unified typed pub/sub channel with automatic backend selection. Topic auto-selects the optimal IPC backend based on message type and usage patterns.

```rust
pub struct Topic<T> { /* fields omitted */ }
```

### Type Parameters

- `T` - Message type. Must implement: `Clone + Send + Sync + Serialize + DeserializeOwned + 'static`

### Backend Selection

Topic automatically selects the fastest backend for your use case — you never need to choose one manually:

| Scenario | Latency | How It Works |
|----------|---------|--------------|
| Same thread, single pub+sub | ~3ns | Direct memory write |
| Same process, 1:1 | ~18ns | Lock-free SPSC ring |
| Same process, many-to-many | ~24–36ns | Lock-free MPMC ring |
| Cross-process, POD types | ~50ns | Shared memory zero-copy |
| Cross-process, general | ~65–167ns | Shared memory with serialization |

### Constructors

#### `new`

```rust
pub fn new(name: impl Into<String>) -> Result<Self>
```

Creates a new Topic with automatic backend selection and auto-sized capacity. Capacity is auto-calculated based on message size (one 4KB page of slots, clamped to 16-1024).

**Parameters:**
- `name` - Topic name or endpoint string

**Returns:** `Result<Topic<T>>`

**Example:**
```rust
let topic: Topic<f32> = Topic::new("sensor.temperature")?;
```

---

#### `with_capacity`

```rust
pub fn with_capacity(name: &str, capacity: u32, slot_size: Option<usize>) -> Result<Self>
```

Creates a Topic with explicit buffer capacity and optional slot size.

**Parameters:**
- `name` - Topic name
- `capacity` - Ring buffer capacity (rounded up to next power of 2)
- `slot_size` - Optional slot size in bytes (`None` uses default)

**Returns:** `Result<Topic<T>>`

**Example:**
```rust
let topic: Topic<Image> = Topic::with_capacity("camera.image", 16, None)?;
```

---

### Methods

#### `send`

```rust
pub fn send(&self, msg: T)
```

Sends a message to the topic. Non-blocking, infallible. Uses bounded retry with "keep last" semantics — if the buffer is full after retry, the message is dropped.

If `.with_logging()` was called, metrics and message summaries are automatically recorded. Otherwise, zero-overhead.

**Parameters:**
- `msg` - Message to send

**Example:**
```rust
self.publisher.send(42.0);
```

---

#### `try_send`

```rust
pub fn try_send(&self, msg: T) -> Result<(), T>
```

Tries to send a message, returning it on failure for explicit retry. Unlike `send()`, does not retry — fails immediately if the buffer is full.

**Parameters:**
- `msg` - Message to send

**Returns:** `Result<(), T>` - `Ok(())` on success, `Err(msg)` returns the message on failure

**Example:**
```rust
match topic.try_send(data) {
    Ok(()) => { /* sent */ }
    Err(returned) => { /* buffer full, try again later */ }
}
```

---

#### `recv`

```rust
pub fn recv(&self) -> Option<T>
```

Receives the next message from the topic. Non-blocking.

**Returns:** `Option<T>` - Some(message) if available, None otherwise

**Example:**
```rust
if let Some(value) = self.subscriber.recv() {
    // Process value
}
```

---

#### `try_recv`

```rust
pub fn try_recv(&self) -> Option<T>
```

Receives the next message without logging. Same as `recv()` but bypasses the logging path entirely — slightly faster when logging is enabled.

**Returns:** `Option<T>` - Some(message) if available, None otherwise

---

#### `read_latest`

```rust
pub fn read_latest(&self) -> Option<T>
where
    T: Copy
```

Returns the most recent message without advancing the consumer position. Calling it multiple times returns the same message until a new one is published. Requires `T: Copy` for safety with multi-consumer backends.

**Returns:** `Option<T>` - The latest published message, or None if no messages have been published

**Example:**
```rust
// Read the latest transform without consuming it
if let Some(transform) = tf_topic.read_latest() {
    apply_transform(transform);
}
```

---

#### `has_message`

```rust
pub fn has_message(&self) -> bool
```

Checks if messages are available without consuming them.

**Returns:** `bool`

---

#### `pending_count`

```rust
pub fn pending_count(&self) -> u64
```

Returns the number of pending (unconsumed) messages in the buffer.

**Returns:** `u64`

---

#### `with_logging`

```rust
pub fn with_logging(self) -> Self
where
    T: LogSummary
```

Enables logging and metrics collection on this topic. When enabled, every `send()` and `recv()` call automatically records metrics and logs message summaries. Requires `T: LogSummary`.

**Returns:** `Self` - The topic with logging enabled

**Example:**
```rust
// Default: zero-overhead, no logging
let fast_topic: Topic<f32> = Topic::new("sensor.temperature")?;

// With logging: automatic metrics + message summaries
let logged_topic: Topic<f32> = Topic::new("sensor.temperature")?.with_logging();
```

---

#### `name`

```rust
pub fn name(&self) -> &str
```

Returns the topic name.

**Returns:** `&str`

---

#### `metrics`

```rust
pub fn metrics(&self) -> TopicMetrics
```

Returns current metrics snapshot (sent/received counts, failure counts, migration count).

**Returns:** `TopicMetrics`

## TopicDescriptor and topics! Macro

```rust
/// Define type-safe topic descriptors
topics! {

// Use the descriptor's name to create a topic
let pub_topic: Topic<f64> = Topic::new(SENSOR_DATA.name())?;
let sub_topic: Topic<f64> = Topic::new(SENSOR_DATA.name())?;
```

### TopicDescriptor

```rust
pub struct TopicDescriptor<T> {
```

## Scheduler

Central orchestrator for node execution with priority-based scheduling.

```rust
pub struct Scheduler { /* fields omitted */ }
```

### Constructors

#### `new`

```rust
pub fn new() -> Self
```

Creates a lightweight scheduler with default settings (~60 Hz tick rate). Detects runtime capabilities (~30-100us) but does **not** apply any OS-level features. Use builder methods to opt in to features.

**Returns:** `Scheduler`

**Example:**
```rust
let mut scheduler = Scheduler::new();
scheduler.add(my_node).order(0).done();
scheduler.run()?;
```

---

#### `deploy`

```rust
pub fn deploy() -> Self
```

Production preset. Applies RT features (best-effort) + BlackBox flight recorder.

**Example:**
```rust
let mut scheduler = Scheduler::deploy();
scheduler.add(motor_ctrl).order(0).rt().done();
scheduler.run()?;
```

---

#### `safety_critical`

```rust
pub fn safety_critical() -> Self
```

Safety-critical preset. 1 kHz tick rate, WCET enforcement, watchdog monitoring.

---

#### `high_performance`

```rust
pub fn high_performance() -> Self
```

High-performance preset. 10 kHz tick rate, parallel execution.

---

#### `hard_realtime`

```rust
pub fn hard_realtime() -> Self
```

Hard real-time preset. 1 kHz tick rate, parallel execution, strict deadlines.

---

#### `deterministic`

```rust
pub fn deterministic() -> Self
```

Deterministic execution preset. 60 Hz, sequential execution, deterministic clock for formal verification and testing.

---

### Preset Summary

| Preset | Tick Rate | Use Case |
|--------|-----------|----------|
| `Scheduler::new()` | 60 Hz | Development, prototyping |
| `Scheduler::deploy()` | 60 Hz | Production deployment |
| `Scheduler::safety_critical()` | 1 kHz | Medical, safety systems |
| `Scheduler::high_performance()` | 10 kHz | Racing, competition |
| `Scheduler::hard_realtime()` | 1 kHz | CNC, aerospace |
| `Scheduler::deterministic()` | 60 Hz | Formal verification, testing |

### Node Management

#### `add`

```rust
pub fn add<N: Node + 'static>(&mut self, node: N) -> NodeBuilder<'_>
```

Adds a node using the fluent builder API. Returns a `NodeBuilder` for configuring the node.

**Returns:** `NodeBuilder` for chaining configuration

**NodeBuilder Methods:**

| Method | Description |
|--------|-------------|
| `.order(n)` | Set execution order (lower = runs first) |
| `.rate_hz(hz)` | Set node-specific tick rate in Hz |
| `.rt()` | Mark as real-time node |
| `.wcet_us(n)` | Set WCET budget in microseconds (implies `.rt()`) |
| `.wcet_ms(n)` | Set WCET budget in milliseconds (implies `.rt()`) |
| `.deadline_us(n)` | Set deadline in microseconds (implies `.rt()`) |
| `.deadline_ms(n)` | Set deadline in milliseconds (implies `.rt()`) |
| `.tier(tier)` | Set explicit execution tier |
| `.failure_policy(policy)` | Override failure handling policy |
| `.done()` | Finalize and register the node |

**NodeTier Options:**
- `NodeTier::UltraFast` - Ultra-fast (&lt;1us), inline execution
- `NodeTier::Fast` - Fast (&lt;10us), inline execution (default)
- `NodeTier::Normal` - Standard scheduling (&lt;100us+)

**Example:**
```rust
use horus::prelude::*;

scheduler.add(safety_monitor).order(0).rt().wcet_us(100).done();
scheduler.add(motor_ctrl).order(5).rt().wcet_us(500).done();
scheduler.add(sensor).order(50).rate_hz(1000.0).done();
scheduler.add(logger).order(200).done();
```

---

#### `set_node_rate`

```rust
pub fn set_node_rate(&mut self, name: &str, rate_hz: f64) -> &mut Self
```

Sets per-node tick rate in Hz.

**Example:**
```rust
scheduler
    .set_node_rate("fast_sensor", 1000.0)  // 1 kHz
    .set_node_rate("slow_logger", 1.0);    // 1 Hz
```

### Example

```rust
use horus::prelude::*;
use std::time::Duration;

fn main() -> Result<()> {
    let mut scheduler = Scheduler::deploy();

    // Add nodes with priorities using fluent API

}
```

## HorusError

Unified error type for all HORUS operations. The prelude exports `HorusError` and `HorusResult<T>`.

```rust
use horus::prelude::*;  // Imports HorusError, HorusResult

#[derive(Debug, Error)]
pub enum HorusError {
    Io(std::io::Error),
    Config(String),
    Communication(String),
    Node { node: String, message: String },
    Memory(String),
    Serialization(String),
    NotFound(String),
    PermissionDenied(String),
    InvalidInput(String),
    AlreadyExists(String),
    Parse(String),
    Unsupported(String),
    Internal { message: String, file: &'static str, line: u32 },
    Contextual { message: String, source: Box<dyn std::error::Error + Send + Sync> },
}
```

### Factory Methods

```rust
impl HorusError {
    pub fn config<S: Into<String>>(msg: S) -> Self;
    pub fn node<S: Into<String>, T: Into<String>>(node: S, message: T) -> Self;
    pub fn communication<S: Into<String>>(msg: S) -> Self;
    pub fn memory<S: Into<String>>(msg: S) -> Self;
    pub fn invalid_input<S: Into<String>>(msg: S) -> Self;
    pub fn internal<S: Into<String>>(msg: S) -> Self;
}
```

### `horus_internal!` Macro

For internal errors with automatic file/line capture:

```rust
use horus::prelude::*;
return Err(horus_internal!("Unexpected state: {:?}", state));
// Expands to: HorusError::Internal { message: "...", file: "src/foo.rs", line: 42 }
```

## Performance

| Scenario | send() Latency |
|----------|---------------|
| Same thread, single pub+sub | ~3ns |
| Same process, 1 producer + 1 consumer | ~18ns |
| Same process, 1:many or many:1 | ~24–26ns |
| Same process, many-to-many | ~36ns |
| Cross-process, POD types | ~50ns |
| Cross-process, 1:1 or 1:many | ~65–85ns |
| Cross-process, many-to-many | ~167ns |

Topic automatically selects the fastest backend based on message type and detected topology.
