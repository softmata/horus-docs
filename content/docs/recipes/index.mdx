# Recipes

A recipe answers a task rather than describing a feature. Where the
[CLI Reference](/development/cli-reference) tells you what `horus run --net` does and
[Configuration Reference](/package-management/configuration) tells you what every
`horus.toml` key means, a recipe is the shape of a whole working setup for one job:
which processes run, what goes in the manifest, and what the wiring looks like.

`/recipes` returned a 404 until now, because the directory had no page of its own — the
individual recipes were in the sidebar but the section index was not there to land on.

## Available recipes

| Recipe | The task |
|--------|----------|
| [ROS 2 Bridge](/recipes/ros2-bridge) | Run HORUS for real-time control while keeping an existing ROS 2 stack for RViz and Nav2, bridging topics between the two |

## Related

Three other collections cover neighbouring ground, and one of them is probably what you
want if nothing above matches:

- [Example Projects](/examples) — ten complete applications in the repository, each with
  its own manifest, robot description and world. Closer to a recipe than anything here
  when your task is "build a robot like *that* one".
- [Tutorials](/tutorials) — the ten-part guided series, in Rust, Python and C++, if you
  want to be walked through the reasoning rather than handed a configuration.
- [Migrating from ROS 2](/tutorials/migrating-from-ros2-rust) — the API mapping, for when
  you are replacing a ROS 2 system rather than bridging to it.
