# Example Projects

Ten complete applications ship in the HORUS repository under
[`examples/`](https://github.com/softmata/horus/tree/main/examples). Each one is a real
project — a `horus.toml`, a `main.rs` or `main.py`, a robot description under `robots/`,
and for six of them a `worlds/` scene — not a snippet. They are what to reach for when you
know what you want to build and would rather see it built once first.

<Callout type="info" title="These are projects; the language pages are snippets">

[Rust Examples](/rust/examples/basic-examples), [Python Examples](/python/examples) and
[C++ Examples](/cpp/examples/basic) show individual API patterns inside this
documentation. The ten below are checked-out, runnable applications with their own
manifests. A nightly CI job runs `horus build` in each of the ten and fails if any of them
stops compiling — so they are kept working, though a break can be up to a day old rather
than caught on the pull request that caused it.

</Callout>

## Running one

Every example is an ordinary HORUS project, so it runs the way yours does:

```bash
git clone https://github.com/softmata/horus.git
cd horus/examples/differential_drive
horus run main.rs
```

Python is the same command:

```bash
cd horus/examples/python_robot
horus run main.py
```

The simulator is optional — the examples publish and subscribe without it. To see the
robot move, start [sim3d](/plugins) in another terminal first:

```bash
sim3d --mode visual --robot robots/<robot>.urdf --world worlds/<world>.yaml
```

While one is running, the usual introspection applies:

```bash
horus topic list
horus topic echo cmd_vel
horus node list
horus monitor
```

## Turning one into your project

There is no `horus new --from <example>`. Copying the directory is the supported path,
and it is two steps:

```bash
cp -r horus/examples/differential_drive my_robot
cd my_robot
# edit horus.toml: change `name = "differential_drive"` to `name = "my_robot"`
horus run main.rs
```

`horus build` regenerates `.horus/Cargo.toml` from `horus.toml` on every build, so
renaming the package in the manifest is enough — there is no second file holding the old
name. Delete the copied `.horus/` directory if one came along; it is a build cache.

<Callout type="tip" title="Copy the manifest, not just the code">

`horus.toml` is where an example's dependencies, `[hardware]` entries and scripts live —
`driver_integration`'s driver table and `robot_arm`'s `horus-tf` dependency are both in
the manifest, not in `src/main.rs`. Copying only the source file is the usual reason a
copied example stops compiling.

</Callout>

## C++ examples

The C++ examples live under
[`horus_cpp/examples/`](https://github.com/softmata/horus/tree/main/horus_cpp/examples)
rather than `examples/`, because they build with CMake against the C++ bindings instead of
through `horus build`:

| Example | What it teaches |
|---------|-----------------|
| `pub_sub_demo.cpp` | Topics, the loan/publish pattern, send-by-copy |
| `multi_node.cpp` | Several nodes in one scheduler — rates, budgets, `on_miss` |
| `obstacle_avoidance.cpp` | Reactive control from a `LaserScan` |
| `camera_publisher.cpp` | Publishing sensor data at a fixed rate |
| `transform_frames.cpp` | Coordinate frames from C++ |
| `params_demo.cpp` | Runtime parameters |

```bash
cargo build -p horus_cpp                      # produces libhorus_cpp.a
cmake -S horus_cpp/examples -B build/cpp-examples
cmake --build build/cpp-examples
```

CMake finds the library under `target/` automatically in a checkout; pass
`-DHORUS_CPP_LIB=...` to point it elsewhere.
