# Static Analysis

<Callout type="info" title="Do I Need This?">

**For most users: Eventually yes.** Static analysis catches bugs before you run code.

**When this page IS useful:**
- Getting weird topic errors at runtime
- Want to catch configuration mistakes early
- Building larger systems with many topics

**Quick answer:** Run `horus check` before running your code. If you get errors, this page explains them.

</Callout>

`horus check` includes static analysis to detect Topic SPSC violations before runtime.

## Topic SPSC Violations

Topic SPSC is Single-Producer-Single-Consumer. Multiple producers or consumers on the same topic causes undefined behavior.

```rust
// WRONG: Two producers on same topic
Topic::new("sensor_data")?;  // Node A
Topic::new("sensor_data")?;  // Node B - SPSC violation!

// FIX: Use Topic for multiple producers
Topic::new("sensor_data")?;  // Supports MPMC
```

## What's Detected

| Pattern | Detected |
|---------|----------|
| `Topic::new("topic")` called twice | Yes |
| `Topic::new("topic")` called twice | Yes |
| Violations across multiple files | Yes |
| Dynamic topic names (`Topic::new(var)`) | No |

## Topic SPSC vs Topic MPMC

| Scenario | Use (round-trip latency) |
|----------|-----|
| Single producer, single consumer | Topic SPSC (~~85ns) |
| Multiple producers or consumers | Topic MPMC (~~167ns) |
