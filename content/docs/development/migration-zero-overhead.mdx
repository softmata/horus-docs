# Migration Guide: Zero-Overhead IPC

This guide helps you migrate from HORUS v0.2.x (embedded introspection) to v0.3+ (zero-overhead IPC with separated introspection).

## Quick Reference

### API Changes at a Glance

| Operation | v0.2.x (Old) | v0.3+ (New) |
|-----------|--------------|-------------|
| Create topic (default) | `Topic::new("name")?` | `Topic::new("name")?` |
| Create topic (with logging) | N/A (always logged) | `Topic::new("name")?.with_logging()` |
| Send | `topic.send(msg)?` | `topic.send(msg)` (infallible) |
| Receive | `topic.recv()` | `topic.recv()` (only method) |

### Return Type Changes

| Method | v0.2.x | v0.3+ |
|--------|--------|-------|
| `send()` | `HorusResult<()>` | `()` (infallible) |
| `recv()` | `Option<T>` | `Option<T>` (unchanged) |

## Step-by-Step Migration

### Step 1: Update `send()` Calls

**Before (v0.2.x):**
```rust
impl Node for MyNode {
    fn tick(&mut self) {
        let data = SensorData { x: 1.0, y: 2.0 };
        self.sensor_pub.send(data).ok();
    }
}
```

**After (v0.3+):**
```rust
impl Node for MyNode {
    fn tick(&mut self) {
        let data = SensorData { x: 1.0, y: 2.0 };
        self.sensor_pub.send(data);
    }
}
```

**Changes:**
- Remove `&mut ctx` parameter from `send()`
- Remove `.ok()` — `send()` is now infallible
- The `tick()` method no longer takes a `ctx` parameter at all

### Step 2: Update `recv()` Calls

**Before (v0.2.x):**
```rust
fn tick(&mut self) {
    if let Some(cmd) = self.cmd_sub.recv() {
        self.process(cmd);
    }
}
```

**After (v0.3+):**
```rust
fn tick(&mut self) {
    if let Some(cmd) = self.cmd_sub.recv() {
        self.process(cmd);
    }
}
```

### Step 3: Remove Error Handling from `send()`

The new `send()` is infallible — it returns `()` instead of `Result`. Ring buffers overwrite the oldest message when full ("keep last" semantics).

**Before (v0.2.x):**
```rust
match self.pub.send(data) {
    Ok(()) => { /* success */ }
    Err(e) => {
        log::error!("Send failed: {:?}", e);
    }
}
```

**After (v0.3+):**
```rust
// Just send — always succeeds
self.pub.send(data);
```

**Key difference:** No error handling needed. Buffer full = oldest message overwritten.

### Step 4: Add Introspection Where Needed

If you were relying on automatic logging from the old `ctx`, add explicit logging calls:

**Option A: Use `.with_logging()` at construction time (requires `T: LogSummary`)**

```rust
use horus::prelude::*;

#[derive(Clone, Copy, Pod, Zeroable)]
#[repr(C)]
struct HealthStatus {
    cpu_usage: f32,
    memory_mb: u32,
}

impl LogSummary for HealthStatus {
    fn log_summary(&self) -> String {
        format!("Health(cpu={:.0}%, mem={}MB)", self.cpu_usage * 100.0, self.memory_mb)
    }
}

struct HealthMonitor {
    // Enable logging at construction time — requires T: LogSummary
    health_pub: Topic<HealthStatus>,
}

impl HealthMonitor {
    fn new() -> Result<Self> {
        Ok(Self {
            health_pub: Topic::new("health_status")?.with_logging(),
        })
    }
}

impl Node for HealthMonitor {
    fn tick(&mut self) {
        let status = HealthStatus {
            cpu_usage: 0.45,
            memory_mb: 512,
        };
        // Just use send() — logging happens automatically
        self.health_pub.send(status);
    }
}
```

**Option B: Use External Tools**

No code changes needed - just use `horus monitor` or `horus topic echo`:

```bash
# Monitor all topics
horus monitor

# Watch specific topic
horus topic echo health_status

# Measure rate
horus topic hz health_status
```

## Pattern-Specific Migration

### Pattern 1: Simple Publisher

**Before:**
```rust
struct SimplePublisher {
    data_pub: Topic<f32>,
}

impl Node for SimplePublisher {
    fn name(&self) -> &'static str { "SimplePublisher" }

    fn tick(&mut self) {
        self.data_pub.send(42.0).ok();
    }
}
```

**After:**
```rust
struct SimplePublisher {
    data_pub: Topic<f32>,
}

impl Node for SimplePublisher {
    fn name(&self) -> &'static str { "SimplePublisher" }

    fn tick(&mut self) {
        self.data_pub.send(42.0);
    }
}
```

### Pattern 2: Simple Subscriber

**Before:**
```rust
struct SimpleSubscriber {
    data_sub: Topic<f32>,
}

impl Node for SimpleSubscriber {
    fn name(&self) -> &'static str { "SimpleSubscriber" }

    fn tick(&mut self) {
        if let Some(data) = self.data_sub.recv() {
            println!("Received: {}", data);
        }
    }
}
```

**After:**
```rust
struct SimpleSubscriber {
    data_sub: Topic<f32>,
}

impl Node for SimpleSubscriber {
    fn name(&self) -> &'static str { "SimpleSubscriber" }

    fn tick(&mut self) {
        if let Some(data) = self.data_sub.recv() {
            println!("Received: {}", data);
        }
    }
}
```

### Pattern 3: Logging in tick()

Since `tick()` no longer receives `ctx`, use standard logging:

```rust
impl Node for MyNode {
    fn tick(&mut self) {
        // Zero-overhead IPC
        if let Some(data) = self.sensor_sub.recv() {
            // Use standard logging
            log::info!("Processing sensor: {:?}", data);

            let result = self.process(data);

            // Zero-overhead send
            self.output_pub.send(result);
        }
    }
}
```

Note: `NodeInfo` is still available in `init()` and `shutdown()` for lifecycle logging.

### Pattern 4: Fire-and-Forget Send

The new API is infallible — ring buffers overwrite the oldest message when full:

**After (v0.3+):**
```rust
fn tick(&mut self) {
    let data = self.compute_output();

    // Just send — always succeeds
    self.output_pub.send(data);
}
```

## node! Macro Migration

If you're using the `node!` macro, the generated code will automatically use the new API.

**Before (v0.2.x macro):**
```rust
node! {
    MySensor {
        pub { readings: f32 -> "sensor.readings" }

        tick() {
            self.readings.send(42.0);
        }
    }
}
```

**After (v0.3+ macro):**
```rust
node! {
    MySensor {
        pub { readings: f32 -> "sensor.readings" }

        tick() {
            self.readings.send(42.0);
        }
    }
}
```

## Implementing LogSummary

To use `.with_logging()`, your message type must implement `LogSummary`:

```rust
use horus::prelude::*;

#[derive(Clone, Copy, Pod, Zeroable)]
#[repr(C)]
struct RobotPose {
    x: f32,
    y: f32,
    theta: f32,
}

impl LogSummary for RobotPose {
    fn log_summary(&self) -> String {
        format!("Pose({:.2}, {:.2}, {:.2}°)", self.x, self.y, self.theta.to_degrees())
    }
}

// Enable logging at construction time
let topic: Topic<RobotPose> = Topic::new("robot_pose")?.with_logging();

// Now send() automatically logs via LogSummary
topic.send(pose);
```

Or use the `horus_message!` macro which auto-implements `LogSummary`:

```rust
horus_message! {
    struct RobotPose {
        x: f32,
        y: f32,
        theta: f32,
    }
}
```

## Common Migration Errors

### Error: "expected 1 argument, found 2"

```
error[E0061]: this method takes 1 argument but 2 arguments were supplied
  --> src/nodes/sensor.rs:42:5
   |
42 |     self.pub.send(data)?;
   |              ^^^^ --- unexpected argument
```

**Fix:** Remove the `&mut ctx` argument:
```rust
self.pub.send(data);
```

### Error: "`with_logging()` requires `LogSummary`"

```
error[E0277]: the trait bound `MyMessage: LogSummary` is not satisfied
```

**Fix:** Implement `LogSummary` for your message type before calling `.with_logging()`:
```rust
impl LogSummary for MyMessage {
    fn log_summary(&self) -> String {
        format!("MyMessage(...)")
    }
}

// Now this works:
let topic = Topic::new("my_topic")?.with_logging();
```

### Error: Unused result from `send()`

If you see warnings about unused `Result`, you're using an old version. Update to v0.3+ where `send()` is infallible:
```rust
// Old - returned Result<(), T>
topic.send(msg).ok();

// New - returns (), no .ok() needed
topic.send(msg);
```

|----------|---------------|---------------|-------------|
| MpmcShm send | ~450-800ns | ~167ns | 2.7-4.8x faster |
| SpscShm send | ~200-350ns | ~85ns | 2.4-4.1x faster |

## Checklist

Before deploying migrated code:

- [ ] All `send(msg, )` calls updated to `send(msg)`
- [ ] All `recv(&mut ctx)` calls updated to `recv()`
- [ ] Error handling removed from `send()` calls (now infallible)
- [ ] `LogSummary` implemented for types used with `.with_logging()`
- [ ] Tests updated and passing
- [ ] Benchmarks verified (should be faster!)
