# Execution Modes

<Callout type="info" title="Quick Answer: Which Mode Should I Use?">

**Use the default.** `Scheduler::new()` gives you deterministic, predictable execution that works for most robots.

| Your Situation | Recommended Setup |
|----------------|------------------|
| Learning HORUS | `Scheduler::new()` with defaults |
| Prototyping | `Scheduler::new()` |
| Need maximum speed | `Scheduler::new()` with `.compute()` execution class on heavy nodes |
| Safety-critical (medical, aerospace) | `Scheduler::new().tick_hz(1000.0)` with `.rt()` execution class |

**Don't overthink this.** Start with `Scheduler::new()` and configure per-node execution classes as needed.

</Callout>

HORUS supports two execution modes to optimize for different robotics scenarios. You configure the scheduler through `Scheduler::new()` and per-node execution classes (`.rt()`, `.compute()`, `.on(topic)`, `.async_io()`) — the scheduler handles the rest.

## Sequential Mode

**The deterministic choice for safety-critical systems.**

Sequential mode is the default. Nodes execute one-by-one in priority order, producing the same execution order every tick.

### How It Works

- Nodes execute one-by-one in priority order
- Same execution order every tick
- Bit-for-bit reproducible runs

### Characteristics

| Metric | Value |
|--------|-------|
| Latency | ~100-500ns per node |
| Deterministic | **Yes** |
| Multi-core | No (single thread) |
| Best For | Safety-critical, certification |

### When to Use

- Medical/surgical robots requiring certification
- Systems needing reproducible behavior
- Debugging complex timing issues
- Formal verification scenarios

Sequential mode is the default when nodes are added with distinct order values. Use `Scheduler::new()` and assign execution classes like `.rt()` for real-time constraints.

```rust,ignore
use horus::prelude::*;

// Safety-critical robot controller — 1 kHz tick, RT execution class
let mut scheduler = Scheduler::new().tick_hz(1000.0);
scheduler.add(safety_monitor).rt().order(0).done();
scheduler.add(controller).rt().order(1).done();
scheduler.run()?;
```

## Parallel Mode

**Multi-core execution for maximum throughput.**

Parallel mode schedules independent nodes on different CPU cores, executing them concurrently while still respecting priority ordering.

### How It Works

- Schedules independent nodes on different cores
- Respects priority ordering
- Uses thread pool for concurrent execution

### Characteristics

| Metric | Value |
|--------|-------|
| Latency | Variable (depends on workload) |
| Deterministic | No |
| Multi-core | **Yes** |
| Best For | Multi-sensor fusion, compute-heavy pipelines |

### When to Use

- Multi-sensor robots
- Compute-heavy pipelines
- Systems with many independent nodes
- When you have multiple CPU cores available

The scheduler uses parallel mode when multiple nodes share the same order value and are configured with execution classes like `.compute()`. Nodes at the same order level can run concurrently across cores:

```rust,ignore
use horus::prelude::*;

let mut scheduler = Scheduler::new();

// These sensor nodes can run in parallel (same order number)
scheduler.add(lidar_node).order(0).done();
scheduler.add(camera_node).order(0).done();
scheduler.add(imu_node).order(0).done();

// Fusion runs after all sensors (higher order number = runs later)
scheduler.add(fusion_node).order(1).done();
scheduler.run()?;
```

## Mode Comparison

| Feature | Sequential | Parallel |
|---------|------------|----------|
| Deterministic | **Yes** | No |
| Multi-core | No | **Yes** |
| Best Latency | 87-313ns | Variable |
| Certification Ready | **Yes** | No |

## Examples

### Safety-Critical System

```rust,ignore
use horus::prelude::*;

// Surgical robot — deterministic, 1 kHz tick with RT execution class
let mut scheduler = Scheduler::new().tick_hz(1000.0);
scheduler.add(safety_monitor).rt().order(0).done();
scheduler.add(force_feedback).rt().order(1).done();
scheduler.add(motion_controller).rt().order(1).done();
scheduler.run()?;
```

### Racing Robot

```rust,ignore
use horus::prelude::*;

// Competition robot — maximum speed, compute-heavy nodes run in parallel
let mut scheduler = Scheduler::new();
scheduler.add(imu_reader).compute().order(0).done();
scheduler.add(motor_controller).compute().order(0).done();
scheduler.run()?;
```

### Multi-Sensor Robot

```rust,ignore
use horus::prelude::*;

// Research robot with many sensors — parallel sensor processing
let mut scheduler = Scheduler::new();

// These run in parallel (same order number)
scheduler.add(lidar).order(0).done();
scheduler.add(camera).order(0).done();
scheduler.add(radar).order(0).done();
scheduler.add(imu).order(0).done();
// Fusion runs after all sensors (higher order number = runs later)
scheduler.add(fusion).order(1).done();
scheduler.run()?;
```
