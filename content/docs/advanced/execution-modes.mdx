# Execution Modes

<Callout type="info" title="Quick Answer: Which Mode Should I Use?">

**Use the default.** `Scheduler::new()` gives you deterministic, predictable execution that works for most robots.

| Your Situation | Recommended Mode |
|----------------|------------------|
| Learning HORUS | Default (`Scheduler::new()`) |
| Prototyping | Default |
| Need maximum speed | `SchedulerConfig::high_performance()` |
| Safety-critical (medical, aerospace) | `SchedulerConfig::safety_critical()` |

**Don't overthink this.** Pick one and change later if needed.

</Callout>

HORUS supports two execution modes to optimize for different robotics scenarios.

## Overview

```rust,ignore
pub enum ExecutionMode {
    Sequential,     // Deterministic, single-threaded
    Parallel,       // Multi-core execution
}
```

## Sequential Mode

**The deterministic choice for safety-critical systems.**

```rust,ignore
use horus::prelude::*;

// Sequential is the default for standard(), deterministic(), and safety_critical()
let config = SchedulerConfig::standard();
// config.execution == ExecutionMode::Sequential
```

### How It Works

- Nodes execute one-by-one in priority order
- Same execution order every tick
- Bit-for-bit reproducible runs

### Characteristics

| Metric | Value |
|--------|-------|
| Latency | ~100-500ns per node |
| Deterministic | **Yes** |
| Multi-core | No (single thread) |
| Best For | Safety-critical, certification |

### When to Use

- Medical/surgical robots requiring certification
- Systems needing reproducible behavior
- Debugging complex timing issues
- Formal verification scenarios

```rust,ignore
// Safety-critical robot controller
let config = SchedulerConfig::safety_critical();
// Automatically uses ExecutionMode::Sequential

let mut scheduler = Scheduler::new().with_config(config);
scheduler.add(safety_monitor).order(0).done();
scheduler.add(controller).order(1).done();
scheduler.run()?;
```

## Parallel Mode

**Multi-core execution for maximum throughput.**

```rust,ignore
use horus::prelude::*;

// high_performance() preset uses Parallel mode
let config = SchedulerConfig::high_performance();
// config.execution == ExecutionMode::Parallel

// Or set it manually on any preset
let mut config = SchedulerConfig::standard();
config.execution = ExecutionMode::Parallel;
```

### How It Works

- Schedules independent nodes on different cores
- Respects priority ordering
- Uses thread pool for concurrent execution

### Characteristics

| Metric | Value |
|--------|-------|
| Latency | Variable (depends on workload) |
| Deterministic | No |
| Multi-core | **Yes** |
| Best For | Multi-sensor fusion, compute-heavy pipelines |

### When to Use

- Multi-sensor robots
- Compute-heavy pipelines
- Systems with many independent nodes
- When you have multiple CPU cores available

```rust,ignore
// These sensor nodes can run in parallel (same order)
scheduler.add(lidar_node).order(0).done();
scheduler.add(camera_node).order(0).done();
scheduler.add(imu_node).order(0).done();

// Fusion runs after all sensors (higher order number = runs later)
scheduler.add(fusion_node).order(1).done();
```

## Mode Comparison

| Feature | Sequential | Parallel |
|---------|------------|----------|
| Deterministic | **Yes** | No |
| Multi-core | No | **Yes** |
| Best Latency | 87-313ns | Variable |
| Certification Ready | **Yes** | No |

## Examples

### Safety-Critical System

```rust,ignore
// Surgical robot - must be deterministic
let config = SchedulerConfig::safety_critical();
// Uses Sequential mode automatically

let mut scheduler = Scheduler::new().with_config(config);
scheduler.add(safety_monitor).order(0).done();
scheduler.add(force_feedback).order(1).done();
scheduler.add(motion_controller).order(1).done();
scheduler.run()?;
```

### Racing Robot

```rust,ignore
// Competition robot - maximum speed
let config = SchedulerConfig::high_performance();
// Uses Parallel mode for multi-core execution

let mut scheduler = Scheduler::new().with_config(config);
scheduler.add(imu_reader).order(0).done();
scheduler.add(motor_controller).order(0).done();
scheduler.run()?;
```

### Multi-Sensor Robot

```rust,ignore
// Research robot with many sensors
let mut config = SchedulerConfig::standard();
config.execution = ExecutionMode::Parallel;

let mut scheduler = Scheduler::new().with_config(config);
// These run in parallel (same order number)
scheduler.add(lidar).order(0).done();
scheduler.add(camera).order(0).done();
scheduler.add(radar).order(0).done();
scheduler.add(imu).order(0).done();
// Fusion runs after all sensors (higher order number = runs later)
scheduler.add(fusion).order(1).done();
scheduler.run()?;
```
