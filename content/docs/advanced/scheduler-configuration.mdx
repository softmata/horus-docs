# Scheduler Configuration

HORUS provides a comprehensive `SchedulerConfig` system that allows you to tune the scheduler for different robotics scenarios - from rapid prototyping to safety-critical medical devices.

## Key Takeaways

After reading this guide, you will understand:
- How to use preset schedulers for common scenarios
- How to configure nodes with the fluent NodeBuilder API
- How to customize scheduler configuration with builder methods
- Advanced timing, fault tolerance, and real-time options

## Quick Start

### Preset Schedulers

For most use cases, use preset constructors that configure everything optimally:

```rust
use horus::prelude::*;

fn main() -> Result<()> {
    // Standard: sequential, circuit breaker, 60Hz
    let scheduler = Scheduler::new();

    // Safety-critical: strict deadlines, watchdogs, memory locking
    let scheduler = Scheduler::safety_critical();

    // High-performance: parallel execution, 10kHz tick rate
    let scheduler = Scheduler::high_performance();

    // Hard real-time: strict WCET, 10ms watchdog, safety monitor
    let scheduler = Scheduler::hard_realtime();

    // Deterministic: reproducible execution for testing/replay
    let scheduler = Scheduler::deterministic();

    Ok(())
}
```

### Adding Nodes with NodeBuilder

Use the fluent API to configure nodes:

```rust
use horus::prelude::*;

fn main() -> Result<()> {
    let mut scheduler = Scheduler::new();

    // Simple node with priority
    scheduler.add(SensorNode::new("lidar"))
        .order(10)
        .done();

    // Real-time node with WCET and deadline
    scheduler.add(MotorController::new("arm"))
        .order(0)           // Highest priority
        .rt()               // Mark as real-time
        .wcet_us(200)       // 200μs max execution
        .deadline_ms(1)     // 1ms deadline
        .done();

    // Node with custom rate
    scheduler.add(TelemetryNode::new())
        .order(200)         // Low priority
        .rate_hz(10.0)      // 10Hz (slower than scheduler)
        .done();

    scheduler.run()?;
    Ok(())
}
```

### Custom Configuration

Start from a preset and modify fields directly:

```rust
use horus::prelude::*;

// Start from a preset and tweak
let mut config = SchedulerConfig::standard();
config.timing.global_rate_hz = 1000.0;             // 1kHz tick rate
config.fault.circuit_breaker_enabled = true;        // Enable circuit breaker
config.realtime.deadline_monitoring = true;          // Monitor deadline misses
config.realtime.max_deadline_misses = 5;             // E-stop after 5 misses

let mut scheduler = Scheduler::new().with_config(config);
```

## Scheduler Presets

### Standard (`Scheduler::new()`)

```rust
let scheduler = Scheduler::new();
```

- **Execution**: Sequential
- **Tick Rate**: 60 Hz
- **Fault Tolerance**: Circuit breaker (5 failures, 3 recovery, 5s timeout)
- **Per-Node Rates**: Enabled
- **Profiling**: Enabled
- **Best for**: Most robotics applications, general purpose

### Safety-Critical

```rust
let scheduler = Scheduler::safety_critical();
```

- **Execution**: Sequential
- **Tick Rate**: 1000 Hz (1kHz)
- **Real-Time**: WCET enforcement, deadline monitoring, watchdogs (100ms), safety monitor, memory locking, SCHED_FIFO
- **Deadline Misses**: 0 (emergency stop on first miss)
- **Recording**: Full recording, 1GB black box
- **CPU**: Pinned to cores 0-1, NUMA-aware

**Best for**: Medical devices, surgical robots, safety-critical systems

### High-Performance

```rust
let scheduler = Scheduler::high_performance();
```

- **Execution**: Parallel
- **Tick Rate**: 10,000 Hz (10kHz)
- **Real-Time**: WCET enforcement, deadline monitoring, memory locking, SCHED_FIFO
- **Deadline Misses**: 10 (tolerates some misses for throughput)
- **Fault Tolerance**: Circuit breaker (3 failures, 100ms timeout)
- **NUMA**: Aware

**Best for**: Racing robots, competition, high-speed control

### Hard Real-Time

```rust
let scheduler = Scheduler::hard_realtime();
```

- **Execution**: Parallel
- **Tick Rate**: 1000 Hz
- **Real-Time**: WCET enforcement, deadline monitoring, watchdogs (10ms), safety monitor, memory locking, SCHED_FIFO
- **Deadline Misses**: 3 (strict but allows brief transients)
- **Fault Tolerance**: Circuit breaker (3 failures)
- **Recording**: Minimal recording, 100MB black box

**Best for**: CNC machines, surgical robots, aerospace

### Deterministic

```rust
let scheduler = Scheduler::deterministic();
```

- **Execution**: Sequential
- **Tick Rate**: 1000 Hz
- **Deterministic**: Virtual time, seeded RNG (seed=42), execution trace recording
- **Recording**: Full recording enabled
- **Black Box**: 100MB flight recorder
- **Best for**: Testing, replay, simulation, safety certification

## NodeBuilder API Reference

The fluent API provides chainable methods for node configuration:

### Priority and Ordering

```rust
scheduler.add(node)
    .order(0)        // Lower = higher priority (0 = highest)
    .done();
```

**Priority Guidelines:**
- **0-9**: Critical real-time (motor control, safety)
- **10-49**: High priority (sensors, fast control loops)
- **50-99**: Normal priority (processing, planning)
- **100-199**: Low priority (logging, diagnostics)
- **200+**: Background (telemetry, non-essential)

### Timing

```rust
scheduler.add(node)
    .rate_hz(100.0)      // Node-specific rate (Hz)
    .wcet_us(200)        // WCET budget (microseconds)
    .wcet_ms(5)          // WCET budget (milliseconds)
    .deadline_us(1000)   // Deadline (microseconds)
    .deadline_ms(10)     // Deadline (milliseconds)
    .done();
```

### Real-Time Flags

```rust
scheduler.add(node)
    .rt()                // Mark as real-time node
    .tier(NodeTier::UltraFast) // Explicit execution tier
    .done();
```

## SchedulerConfig Preset Methods

Use preset factory methods, then customize by mutating fields directly:

| Method | Description |
|--------|-------------|
| `SchedulerConfig::standard()` | General-purpose (60Hz, circuit breaker, profiling) |
| `SchedulerConfig::safety_critical()` | Medical/surgical (1kHz, WCET, watchdog, safety monitor) |
| `SchedulerConfig::high_performance()` | Racing/competition (10kHz, parallel, WCET) |
| `SchedulerConfig::hard_realtime()` | Hard RT (1kHz, parallel, 10ms watchdog) |
| `SchedulerConfig::deterministic()` | Replay/testing (1kHz, virtual time, recording) |
| `SchedulerConfig::deploy()` | Production (60Hz, deadline monitoring, 16MB black box) |
| `SchedulerConfig::minimal()` | Bare minimum (60Hz, everything disabled) |

### Customizing a Preset

```rust
let mut config = SchedulerConfig::safety_critical();
config.timing.global_rate_hz = 500.0;              // Override tick rate
config.fault.circuit_breaker_enabled = true;        // Toggle circuit breaker
config.realtime.wcet_enforcement = false;           // Toggle WCET enforcement
config.monitoring.black_box_enabled = true;
config.monitoring.black_box_size_mb = 256;          // 256MB black box

let mut scheduler = Scheduler::new().with_config(config);
```

## Configuration Sections (Advanced)

For direct struct access, modify preset configs:

### TimingConfig

```rust
pub struct TimingConfig {
    /// Global tick rate in Hz (default: 60)
    pub global_rate_hz: f64,
    /// Enable per-node rate control
    pub per_node_rates: bool,
}
```

### FaultConfig

```rust
pub struct FaultConfig {
    /// Enable circuit breaker pattern
    pub circuit_breaker_enabled: bool,
    /// Max failures before circuit opens
    pub max_failures: u32,
    /// Success count to close circuit
    pub recovery_threshold: u32,
    /// Circuit timeout in milliseconds
    pub circuit_timeout_ms: u64,
}
```

### RealTimeConfig

```rust
pub struct RealTimeConfig {
    /// Enable WCET enforcement
    pub wcet_enforcement: bool,
    /// Enable deadline monitoring
    pub deadline_monitoring: bool,
    /// Enable watchdog timers
    pub watchdog_enabled: bool,
    /// Default watchdog timeout in milliseconds
    pub watchdog_timeout_ms: u64,
    /// Enable safety monitor
    pub safety_monitor: bool,
    /// Maximum deadline misses before emergency stop
    pub max_deadline_misses: u64,
    /// Memory locking (mlockall)
    pub memory_locking: bool,
    /// Use real-time scheduling class (SCHED_FIFO/RR)
    pub rt_scheduling_class: bool,
}
```

### ResourceConfig

```rust
pub struct ResourceConfig {
    /// CPU cores to use (None = all cores) - Linux only
    pub cpu_cores: Option<Vec<usize>>,
    /// Enable NUMA awareness - Linux only
    pub numa_aware: bool,
}
```

### MonitoringConfig

```rust
pub struct MonitoringConfig {
    /// Enable runtime profiling
    pub profiling_enabled: bool,
    /// Metrics export interval in ms
    pub metrics_interval_ms: u64,
    /// Enable black box recording
    pub black_box_enabled: bool,
    /// Black box buffer size in MB
    pub black_box_size_mb: usize,
    /// Telemetry export endpoint (e.g., "udp://localhost:9999")
    pub telemetry_endpoint: Option<String>,
}
```

### DeterministicConfig

Controls deterministic execution for testing and replay:

```rust
pub struct DeterministicConfig {
    /// Seed for deterministic RNG (default: 42)
    pub seed: u64,
    /// Whether to use virtual time (ignore wall clock)
    pub virtual_time: bool,
    /// Fixed tick duration in nanoseconds (for virtual time)
    pub tick_duration_ns: u64,
    /// Whether to record execution trace
    pub record_trace: bool,
}
```

Enable via `config.deterministic = Some(DeterministicConfig::default())`.

### RecordingConfigYaml

Controls record/replay:

```rust
pub struct RecordingConfigYaml {
    pub enabled: bool,
    pub session_name: Option<String>,
    pub compress: bool,
    pub interval: u32,
    pub output_dir: Option<String>,
    pub max_size_mb: usize,
    pub include_nodes: Vec<String>,
    pub exclude_nodes: Vec<String>,
    pub record_inputs: bool,
    pub record_outputs: bool,
    pub record_timing: bool,
}
```

Use presets: `RecordingConfigYaml::full()`, `RecordingConfigYaml::debug()`, or `RecordingConfigYaml::minimal()`.

### Direct Struct Modification

```rust
let mut config = SchedulerConfig::safety_critical();
config.timing.global_rate_hz = 500.0;
config.fault.circuit_breaker_enabled = true;
config.fault.max_failures = 3;
config.realtime.watchdog_timeout_ms = 50;
config.resources.cpu_cores = Some(vec![2, 3]);
config.monitoring.black_box_size_mb = 512;
config.deterministic = Some(DeterministicConfig::default());

let scheduler = Scheduler::new().with_config(config);
```

## OS Priority Configuration

Set real-time OS scheduling priority:

```rust
let scheduler = Scheduler::new();
scheduler.set_os_priority(50)?;  // Set SCHED_FIFO priority 1-99
```

Note: Requires root/CAP_SYS_NICE capability on Linux.

## Python API

The Python bindings provide a similar fluent API with Python-style method names:

```python
from horus import Scheduler, SchedulerConfig

# Preset configurations
config = SchedulerConfig.standard()
config = SchedulerConfig.safety_critical()
config = SchedulerConfig.high_performance()
config = SchedulerConfig.hard_realtime()
config = SchedulerConfig.deterministic()

# Builder pattern
config = (SchedulerConfig.builder()
    .rate_hz(1000.0)
    .watchdog_ms(50)
    .enable_circuit_breaker()
    .enable_deadline_monitoring()
    .wcet()
    .memory_lock()
    .rt_scheduling()
    .max_misses(5)
    .build())

# Direct field access (all fields are get/set)
config = SchedulerConfig.standard()
config.tick_rate = 500.0
config.watchdog_enabled = True
config.watchdog_timeout_ms = 50
```
