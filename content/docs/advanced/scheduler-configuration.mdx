# Scheduler Configuration

HORUS provides a comprehensive `SchedulerConfig` system that allows you to tune the scheduler for different robotics scenarios - from rapid prototyping to safety-critical medical devices.

## Key Takeaways

After reading this guide, you will understand:
- How to use preset schedulers for common scenarios
- How to configure nodes with the fluent NodeBuilder API
- How to customize scheduler configuration with flat setters
- Advanced timing, fault tolerance, and real-time options

## Quick Start

### Preset Schedulers

For most use cases, use preset constructors that configure everything optimally:

```rust
use horus::prelude::*;

fn main() -> Result<()> {
    // Default: deterministic scheduler
    let scheduler = Scheduler::new();

    // Safety-critical: strict deadlines, watchdogs, memory locking
    let scheduler = Scheduler::safety_critical();

    // High-performance: parallel execution, 10kHz tick rate
    let scheduler = Scheduler::high_performance();

    // Hard real-time: formal verification, strict WCET
    let scheduler = Scheduler::hard_realtime();

    // Deterministic: reproducible execution for testing
    let scheduler = Scheduler::deterministic();

    Ok(())
}
```

### Adding Nodes with NodeBuilder

Use the fluent API to configure nodes:

```rust
use horus::prelude::*;

fn main() -> Result<()> {
    let mut scheduler = Scheduler::new();

    // Simple node with priority
    scheduler.add(SensorNode::new("lidar"))
        .order(10)
        .done();

    // Real-time node with WCET and deadline
    scheduler.add(MotorController::new("arm"))
        .order(0)           // Highest priority
        .rt()               // Mark as real-time
        .wcet_us(200)       // 200μs max execution
        .deadline_ms(1)     // 1ms deadline
        .done();

    // Node with custom rate
    scheduler.add(TelemetryNode::new())
        .order(200)         // Low priority
        .rate_hz(10.0)      // 10Hz (slower than scheduler)
        .no_logging()       // Disable metrics
        .done();

    scheduler.run()?;
    Ok(())
}
```

### Custom Configuration with Flat Setters

Build custom configurations with chainable methods:

```rust
use horus::prelude::*;

// Start from minimal and add what you need
let config = SchedulerConfig::builder()
    .rate_hz(1000.0)              // 1kHz tick rate
    .watchdog_ms(50)              // 50ms watchdog
    .circuit_breaker()            // Enable circuit breaker
    .deadline_monitoring()        // Monitor deadline misses
    .build();

let mut scheduler = Scheduler::new().with_config(config);
```

## Scheduler Presets

### Default (`Scheduler::new()`)

```rust
let scheduler = Scheduler::new();
```

- **Execution**: Sequential (deterministic)
- **Tick Rate**: ~60 Hz
- **Deterministic**: Yes from tick 0
- **Best for**: Most robotics applications, safety-critical, testing

### Safety-Critical

```rust
let scheduler = Scheduler::safety_critical();
```

- **Execution**: Sequential (deterministic)
- **Tick Rate**: 1000 Hz (1kHz)
- **Jitter**: \<10μs (ultra-low)
- **Deadline Policy**: Panic (fail-safe)
- **Real-Time**: Full WCET enforcement, watchdogs, memory locking, SCHED_FIFO

**Best for**: Medical devices, surgical robots, safety-critical systems

### High-Performance

```rust
let scheduler = Scheduler::high_performance();
```

- **Execution**: Parallel
- **Tick Rate**: 10,000 Hz (10kHz)
- **Jitter**: \<100μs
- **Deadline Policy**: Skip (maintain throughput)
- **Real-Time**: WCET enforcement, memory locking, SCHED_FIFO

**Best for**: Racing robots, competition, high-speed control

### Hard Real-Time

```rust
let scheduler = Scheduler::hard_realtime();
```

- **Execution**: Parallel
- **Tick Rate**: 1000 Hz
- **Jitter**: \<5μs
- **Deadline Policy**: Panic
- **Real-Time**: Full enforcement, 10ms watchdog, formal verification

**Best for**: CNC machines, surgical robots, aerospace

### Deterministic

```rust
let scheduler = Scheduler::deterministic();
```

- **Execution**: Sequential
- **Tick Rate**: 60 Hz
- **Deterministic**: Strict (no parallel)
- **Best for**: Testing, replay, simulation

## NodeBuilder API Reference

The fluent API provides chainable methods for node configuration:

### Priority and Ordering

```rust
scheduler.add(node)
    .order(0)        // Lower = higher priority (0 = highest)
    .priority(0)     // Alias for order()
    .done();
```

**Priority Guidelines:**
- **0-9**: Critical real-time (motor control, safety)
- **10-49**: High priority (sensors, fast control loops)
- **50-99**: Normal priority (processing, planning)
- **100-199**: Low priority (logging, diagnostics)
- **200+**: Background (telemetry, non-essential)

### Timing

```rust
scheduler.add(node)
    .rate_hz(100.0)      // Node-specific rate (Hz)
    .wcet_us(200)        // WCET budget (microseconds)
    .wcet_ms(5)          // WCET budget (milliseconds)
    .deadline_us(1000)   // Deadline (microseconds)
    .deadline_ms(10)     // Deadline (milliseconds)
    .done();
```

### Real-Time Flags

```rust
scheduler.add(node)
    .rt()                // Mark as real-time node
    .tier(NodeTier::UltraFast) // Explicit execution tier
    .done();
```

### Logging

```rust
scheduler.add(node)
    .logging()           // Enable logging (default)
    .no_logging()        // Disable logging
    .done();
```

## SchedulerConfig Flat Setters

Build configurations without nested structs:

### Timing

```rust
SchedulerConfig::builder()
    .rate_hz(1000.0)     // Global tick rate
```

### Watchdog

```rust
SchedulerConfig::builder()
    .watchdog_ms(100)    // Enable with 100ms timeout
    .no_watchdog()       // Disable watchdog
```

### Circuit Breaker

```rust
SchedulerConfig::builder()
    .circuit_breaker()      // Enable
    .no_circuit_breaker()   // Disable
```

### Real-Time Features

```rust
SchedulerConfig::builder()
    .deadline_monitoring()  // Enable deadline monitoring
    .wcet()                 // Enable WCET enforcement
    .memory_lock()          // Lock memory (mlockall)
    .rt_scheduling()        // Use SCHED_FIFO
    .safety_monitor()       // Enable safety monitor
    .max_deadline_misses(5) // E-stop after 5 misses
```

### Fault Tolerance

```rust
SchedulerConfig::builder()
    .blackbox_mb(256)       // 256MB black box
    .no_blackbox()          // Disable black box
```

### Resources

```rust
SchedulerConfig::builder()
    .cpu_cores(&[2, 3])     // Pin to cores 2-3
```

### Complete Example

```rust
let config = SchedulerConfig::builder()
    .rate_hz(1000.0)
    .watchdog_ms(50)
    .circuit_breaker()
    .deadline_monitoring()
    .max_deadline_misses(3)
    .memory_lock()
    .cpu_cores(&[0, 1])
    .build();

let mut scheduler = Scheduler::new().with_config(config);
```

## Configuration Sections (Advanced)

For direct struct access, modify preset configs:

### TimingConfig

```rust
pub struct TimingConfig {
    /// Global tick rate in Hz (default: 60)
    pub global_rate_hz: f64,
    /// Enable per-node rate control
    pub per_node_rates: bool,
}
```

### FaultConfig

```rust
pub struct FaultConfig {
    /// Enable circuit breaker pattern
    pub circuit_breaker_enabled: bool,
    /// Max failures before circuit opens
    pub max_failures: u32,
    /// Success count to close circuit
    pub recovery_threshold: u32,
    /// Circuit timeout in milliseconds
    pub circuit_timeout_ms: u64,
}
```

### RealTimeConfig

```rust
pub struct RealTimeConfig {
    /// Enable WCET enforcement
    pub wcet_enforcement: bool,
    /// Enable deadline monitoring
    pub deadline_monitoring: bool,
    /// Enable watchdog timers
    pub watchdog_enabled: bool,
    /// Default watchdog timeout in milliseconds
    pub watchdog_timeout_ms: u64,
    /// Enable safety monitor
    pub safety_monitor: bool,
    /// Maximum deadline misses before emergency stop
    pub max_deadline_misses: u64,
    /// Memory locking (mlockall)
    pub memory_locking: bool,
    /// Use real-time scheduling class (SCHED_FIFO/RR)
    pub rt_scheduling_class: bool,
}
```

### ResourceConfig

```rust
pub struct ResourceConfig {
    /// CPU cores to use (None = all cores) - Linux only
    pub cpu_cores: Option<Vec<usize>>,
    /// Enable NUMA awareness - Linux only
    pub numa_aware: bool,
}
```

### Direct Struct Modification

```rust
let mut config = SchedulerConfig::safety_critical();
config.timing.global_rate_hz = 500.0;
config.fault.circuit_breaker_enabled = true;
config.fault.max_failures = 3;
config.realtime.watchdog_timeout_ms = 50;
config.resources.cpu_cores = Some(vec![2, 3]);  // Vec<usize> for struct field

let scheduler = Scheduler::new().with_config(config);
```

## OS Priority Configuration

Set real-time OS scheduling priority:

```rust
let scheduler = Scheduler::new();
scheduler.set_os_priority(50)?;  // Set SCHED_FIFO priority 1-99
```

Note: Requires root/CAP_SYS_NICE capability on Linux.

## Configuration Comparison

| Setting | Default | Safety-Critical | High-Performance | Hard-RT |
|---------|---------|-----------------|------------------|---------|
| Execution | Sequential | Sequential | Parallel | Parallel |
| Tick Rate | 60 Hz | 1 kHz | 10 kHz | 1 kHz |
| Max Jitter | - | 10μs | 100μs | 5μs |
| Deadline Miss | - | Panic | Skip | Panic |
| WCET Enforce | No | Yes | Yes | Yes |
| Watchdog | No | Yes (100ms) | No | Yes (10ms) |
| Memory Lock | No | Yes | Yes | Yes |
| SCHED_FIFO | No | Yes | Yes | Yes |
| Deterministic | Yes | Yes | With profile | With profile |

## Python API

The Python bindings provide the same fluent API:

```python
from horus import Scheduler, SchedulerConfig

# Preset configurations
config = SchedulerConfig.standard()
config = SchedulerConfig.safety_critical()
config = SchedulerConfig.high_performance()

# Builder pattern
config = (SchedulerConfig.builder()
    .rate_hz(1000.0)
    .watchdog_ms(50)
    .enable_circuit_breaker()
    .enable_deadline_monitoring()
    .build())
```
