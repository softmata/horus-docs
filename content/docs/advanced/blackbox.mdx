# BlackBox Flight Recorder

The BlackBox flight recorder provides continuous event logging in a circular buffer for post-mortem analysis. Like an aircraft flight recorder, it captures all significant events leading up to failures.

## Overview

The BlackBox system:
- Records scheduler, node, and safety events in a circular buffer
- Limits memory usage with configurable buffer size
- Filters anomalies (errors, deadline misses, emergency stops)
- Integrates directly with the Scheduler

## Enabling BlackBox

### Via Scheduler Builder (Recommended)

```rust
use horus::prelude::*;

// Enable with 16MB buffer
let scheduler = Scheduler::new()
    .with_blackbox(16);  // 16MB flight recorder
```

### Via Deploy Preset

The `deploy()` preset enables blackbox automatically with 16MB:

```rust
use horus::prelude::*;

// Production preset: RT features + blackbox + profiling
let scheduler = Scheduler::deploy();
```

### Via SchedulerConfig

```rust
use horus::prelude::*;

// Using the builder method
let config = SchedulerConfig::standard()
    .with_black_box(true, 10);  // Enabled with 10MB buffer

let scheduler = Scheduler::new().with_config(config);

// Or set fields directly
let mut config = SchedulerConfig::standard();
config.monitoring.black_box_enabled = true;
config.monitoring.black_box_size_mb = 10;

let scheduler = Scheduler::new().with_config(config);
```

### Standalone

```rust
use horus::prelude::*;

// Create a standalone blackbox (10MB buffer)
let mut blackbox = BlackBox::new(10);
```

Passing `0` to `BlackBox::new()` disables recording (the default).

## Event Types

The BlackBox records 11 event types covering all critical system operations:

| Event | Fields | Description |
|-------|--------|-------------|
| `SchedulerStart` | `name`, `node_count`, `config` | Scheduler initialization |
| `SchedulerStop` | `reason`, `total_ticks` | Scheduler shutdown |
| `NodeAdded` | `name`, `priority` | New node registered |
| `NodeTick` | `name`, `duration_us`, `success` | Node execution completed |
| `NodeError` | `name`, `error` | Node execution failed |
| `DeadlineMiss` | `name`, `deadline_us`, `actual_us` | Node missed its deadline |
| `WCETViolation` | `name`, `budget_us`, `actual_us` | Node exceeded WCET budget |
| `CircuitBreakerChange` | `name`, `new_state`, `failure_count` | Circuit breaker state transition |
| `LearningComplete` | `duration_ms`, `tier_summary` | Profiling learning phase finished |
| `EmergencyStop` | `reason` | Emergency stop triggered |
| `Custom` | `category`, `message` | User-defined events |

## Recording Events

When using the Scheduler, events are recorded **automatically**:
- `SchedulerStart` on `run()` / `run_with_config()`
- `NodeTick` for each node execution
- `EmergencyStop` when triggered
- `SchedulerStop` on shutdown

You can also record events manually:

```rust
use horus::prelude::*;

let mut blackbox = BlackBox::new(10);

// Record custom events
blackbox.record(BlackBoxEvent::Custom {
    category: "sensor".to_string(),
    message: "IMU calibration started".to_string(),
});

// Advance tick counter (call each scheduler tick)
blackbox.tick();

// Record node execution
blackbox.record(BlackBoxEvent::NodeTick {
    name: "sensor_node".to_string(),
    duration_us: 150,
    success: true,
});

// Record errors
blackbox.record(BlackBoxEvent::NodeError {
    name: "motor_controller".to_string(),
    error: "I2C timeout".to_string(),
});

// Record deadline misses
blackbox.record(BlackBoxEvent::DeadlineMiss {
    name: "critical_node".to_string(),
    deadline_us: 1000,
    actual_us: 1500,
});
```

## Querying Events

### Get All Events

```rust
let events = blackbox.get_events();
println!("Total events: {}", events.len());

for record in &events {
    println!("[tick {}] {:?}", record.tick, record.event);
}
```

Each `BlackBoxRecord` contains:
- `timestamp_us` — Microseconds since epoch
- `tick` — Monotonic tick counter
- `event` — The `BlackBoxEvent`

### Get Anomalies

Filter for error-related events (errors, deadline misses, WCET violations, circuit breaker changes, emergency stops):

```rust
let anomalies = blackbox.get_anomalies();
for record in &anomalies {
    println!("[tick {}] {:?}", record.tick, record.event);
}
```

### Buffer Info

```rust
println!("Buffer size: {}", blackbox.len());
println!("Is empty: {}", blackbox.is_empty());

// Clear all recorded events
blackbox.clear();
```

## Accessing from Scheduler

The Scheduler provides read and write access to its blackbox:

```rust
use horus::prelude::*;

let mut scheduler = Scheduler::new()
    .with_blackbox(16);

// Read-only access
if let Some(bb) = scheduler.blackbox() {
    let events = bb.get_events();
    let anomalies = bb.get_anomalies();
    println!("Recorded {} events, {} anomalies", events.len(), anomalies.len());
}

// Mutable access (for recording custom events)
if let Some(bb) = scheduler.blackbox_mut() {
    bb.record(BlackBoxEvent::Custom {
        category: "deploy".to_string(),
        message: "Firmware update started".to_string(),
    });
}
```

## Thread-Safe Usage

For multi-threaded applications, use the shared blackbox wrapper:

```rust
use horus::prelude::*;
use std::sync::Arc;

// Create thread-safe blackbox
let blackbox: SharedBlackBox = create_shared_blackbox(10);

// Use from multiple threads
let bb_clone = Arc::clone(&blackbox);
std::thread::spawn(move || {
    let mut bb = bb_clone.lock().unwrap();
    bb.record(BlackBoxEvent::Custom {
        category: "thread".to_string(),
        message: "Worker started".to_string(),
    });
});
```

## Configuration

| Parameter | Default | Description |
|-----------|---------|-------------|
| Buffer size | 0 (disabled) | Set via `BlackBox::new(mb)` or `with_blackbox(mb)` |
| Records per MB | ~5,000 | Estimated at ~200 bytes per record |
| Max pre-allocated | 100,000 records | Initial capacity cap |
| Min buffer | 1,000 records | Minimum regardless of size |

### Preset Sizes

| Use Case | Recommended Size |
|----------|-----------------|
| Development | 1-5 MB |
| Production | 10-50 MB |
| Long-running systems | 50-100 MB |

The `deploy()` preset uses 16MB. The `safety_critical()` preset uses 1024MB.

## Post-Mortem Debugging

After a failure, use the blackbox to investigate what happened:

```rust
use horus::prelude::*;

let mut scheduler = Scheduler::new()
    .with_blackbox(16);

// ... run application ...

// After a failure, inspect the blackbox
if let Some(bb) = scheduler.blackbox() {
    let anomalies = bb.get_anomalies();
    println!("=== ANOMALIES ({}) ===", anomalies.len());
    for record in &anomalies {
        println!("[tick {}] {:?}", record.tick, record.event);
    }

    // Look at all events around the failure
    let all_events = bb.get_events();
    println!("\n=== LAST {} EVENTS ===", all_events.len());
    for record in all_events.iter().rev().take(20) {
        println!("[tick {}] {:?}", record.tick, record.event);
    }
}
```

## Circular Buffer Behavior

The blackbox uses a circular buffer — when full, the oldest events are discarded:

```
Buffer capacity: 50,000 records (10MB)

Event 1 → [1, _, _, _, _]     New events fill the buffer
Event 2 → [1, 2, _, _, _]
...
Event N → [1, 2, ..., N-1, N]  Buffer full
Event N+1 → [2, 3, ..., N, N+1]  Oldest dropped
```

This ensures bounded memory usage while keeping the most recent events for debugging.
