# Communication Backends

HORUS automatically selects the optimal communication backend based on topology — no configuration needed. Every topic is shared-memory backed. HORUS picks one of five SHM backends — FanoutShm, PodShm, MpscShm, SpmcShm, SpscShm — from the publisher/subscriber topology and whether the message type is POD. Cross-machine replication is available separately via the opt-in `net` feature.

<Callout type="info" title="Network Transport Is Opt-In, Not Absent">

HORUS ships transparent LAN replication over UDP in the `horus_net` crate. It is opt-in, not absent: build the `horus` crate with `--features net`, or run `horus run --net`. Replication auto-starts on `scheduler.run()`, discovers peers by UDP multicast (default group `224.0.69.72`, port `9100`), and costs ~50μs across the LAN. Configure it with `[network]` in `horus.toml` or `HORUS_NET_*` env vars; disable it with `.network(false)` or `HORUS_NO_NETWORK=1`. Zenoh is **not** the transport — it is an optional bridge package for cross-subnet/WiFi (`horus install horus-zenoh`).

</Callout>

## Automatic Backend Selection

When you call `Topic::new("name")`, HORUS automatically detects the optimal backend based on the number of publishers, subscribers, and whether the message type is POD:

```rust,ignore
use horus::prelude::*;

// Just create a topic — backend is auto-selected
let topic = Topic::<CmdVel>::new("motors.cmd_vel")?;
topic.send(CmdVel::new(1.0, 0.0));
```

No configuration needed. The backend upgrades and downgrades dynamically as participants join and leave.

## Communication Paths

Every topic is shared-memory backed, so every backend is cross-process. HORUS picks one of five SHM backends from the publisher/subscriber topology and whether the message type is POD:

| Backend | Latency | Detection Criteria |
|---------|---------|-------------------|
| FanoutShm | ~40ns | pubs>1, subs>1, !is_pod (broadcast) |
| PodShm | ~50ns | 1→many / 0→many, is_pod (broadcast) |
| MpscShm | ~65ns | pubs>1, subs<=1 |
| SpmcShm | ~70ns | multi-consumer, non-POD |
| SpscShm | ~85ns | pubs<=1, subs<=1 |

The backend is selected based on:
- **Topology**: Number of publishers and subscribers
- **Data type**: POD (fixed-size, memcpy-able) types get the dedicated zero-copy path; variable-size types are serialized (~167ns)

Cross-machine replication is available separately via the opt-in `net` feature.

## Dynamic Migration

HORUS dynamically migrates between backends as topology changes:

```
Single publisher + single subscriber
  → SpscShm, ~85ns

Second subscriber joins (non-POD payload)
  → SpmcShm, ~70ns

A second publisher joins as well
  → FanoutShm, ~40ns

All but one publisher and one subscriber disconnect
  → SpscShm, ~85ns
```

Migration is transparent — `send()` and `recv()` calls are unaffected.

## Performance Characteristics

| Metric | Shared Memory |
|--------|---------------|
| Latency | 40-85ns |
| Throughput | Millions msg/s |
| Zero-copy | Yes (via mmap) |
| Cross-machine | Yes — opt-in via the `net` feature / `horus run --net`, ~50μs over LAN |

## Network Transport (LAN replication)

Cross-machine topics ship today as the `horus_net` UDP replicator. It is opt-in — build the `horus` crate with `--features net`, or run `horus run --net`:

| Transport | Latency | Use Case |
|-----------|---------|----------|
| Shared Memory | 40-85ns | Same-machine IPC |
| UDP LAN replication (`net` feature) | ~50μs | Multi-robot, cross-machine topics |

`Topic::new()` continues to auto-select the optimal SHM backend either way. With the `net` feature enabled, replication activates automatically whenever remote horus peers are found on the LAN; topics you subscribe to but do not publish are imported by default (`import = "auto"`). Opt out with `.network(false)`, `HORUS_NO_NETWORK=1`, or `[network] enabled = false`; narrow the surface with `[network] import` / `HORUS_NET_IMPORT` and `[network] deny_export`.

Zenoh is not the transport. It is an optional bridge package (`horus install horus-zenoh`) for cases UDP multicast cannot reach — cross-subnet or WiFi links.
