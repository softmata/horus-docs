# Network Backends

<Callout type="warn" title="Planned Feature">

Zenoh network transport is **planned but not yet implemented**. The configuration API (`ZenohEndpointConfig`, YAML topic config) exists and parses correctly, but no actual network transport backend is wired up yet. HORUS currently operates as a **local shared memory IPC framework only**. This page documents the configuration scaffolding that is in place for the upcoming network transport layer.

</Callout>

HORUS uses shared memory for local communication (<1μs latency). Zenoh network transport configuration is scaffolded for future multi-robot, cloud, and ROS2 interoperability.

## Communication Architecture

| Transport | Latency | Use Case |
|-----------|---------|----------|
| **Shared Memory** | ~85ns | Same-machine IPC (default) |
| **Zenoh** | ~100μs | Multi-robot, cloud, ROS2 interop |

Most HORUS applications only need shared memory. Zenoh is for when nodes run on different machines or you need to bridge with ROS2.

## Zenoh Transport

Zenoh provides peer-to-peer mesh networking with optional cloud connectivity. HORUS integrates Zenoh through the `ZenohEndpointConfig` for Topic transport.

### Enabling Zenoh

```toml
[dependencies]
horus_core = { version = "0.1", features = ["zenoh-transport"] }
```

### Configuration

Zenoh endpoints are configured through `ZenohEndpointConfig`:

```rust
pub struct ZenohEndpointConfig {
    /// Enable ROS2 compatibility mode (uses rt/{topic} naming)
    pub ros2_mode: bool,
    /// ROS2 domain ID (0-232), only used when ros2_mode is true
    pub ros2_domain_id: u32,
    /// Endpoints to connect to (routers or peers)
    /// Format: "tcp/192.168.1.1:7447" or "udp/192.168.1.1:7447"
    pub connect: Vec<String>,
    /// Endpoints to listen on
    /// Format: "tcp/0.0.0.0:7447"
    pub listen: Vec<String>,
    /// Namespace prefix for topics (default: "horus")
    pub namespace: Option<String>,
    /// Enable shared memory transport for local communication
    pub shared_memory: bool,
    /// Serialization format: "bincode" (default), "json", "cdr" (ROS2)
    pub serialization: Option<String>,
    /// QoS reliability: "best_effort" (default) or "reliable"
    pub reliability: Option<String>,
    /// QoS priority (0-7, higher = more important)
    pub priority: Option<u8>,
    /// Express mode (skip batching for low latency)
    pub express: bool,
}
```

### YAML Configuration

Configure topics with Zenoh transport in your `horus.yaml`:

```yaml
topics:
  - name: cmd_vel
    transport: zenoh
    zenoh:
      connect:
        - "tcp/192.168.1.100:7447"
      namespace: robot1
      reliability: reliable
      priority: 5
      express: true

  - name: sensor_data
    transport: zenoh
    zenoh:
      ros2_mode: true
      ros2_domain_id: 0
      serialization: cdr
```

### Topic Transport Types (Planned)

The `EndpointConfig` defines these transport types for future use:

| Transport | Description | Config Syntax |
|-----------|-------------|---------------|
| `local` | Shared memory (same machine) | Default (currently the only working transport) |
| `localhost` | UDP loopback | `transport: localhost` |
| `router` | Via HORUS router | `transport: router` |
| `multicast` | UDP multicast | `transport: multicast` |
| `direct` | Direct UDP | `transport: direct` with `host`/`port` |
| `zenoh` | Zenoh transport | `transport: zenoh` with `zenoh:` section |

<Callout type="info">
Currently only `local` (shared memory) transport is implemented. `Topic::new("name")` always creates a local shared memory topic. The `@` endpoint syntax shown in `EndpointConfig` is for configuration purposes only and is not parsed by `Topic::new()`.
</Callout>

### ROS2 Interoperability

When `ros2_mode` is enabled, HORUS automatically maps topic names to ROS2 DDS conventions:

| HORUS Topic | Zenoh Key Expression | ROS2 Topic |
|-------------|---------------------|------------|
| `/cmd_vel` | `rt/cmd_vel` | `/cmd_vel` |
| `/robot/odom` | `rt/robot/odom` | `/robot/odom` |

Set `serialization: "cdr"` for wire-compatible ROS2 message encoding.

### Multi-Robot Setup

Connect multiple robots through Zenoh peers:

```yaml
# Robot 1
topics:
  - name: robot1/odom
    transport: zenoh
    zenoh:
      listen:
        - "tcp/0.0.0.0:7447"
      namespace: fleet

# Robot 2
topics:
  - name: robot2/odom
    transport: zenoh
    zenoh:
      connect:
        - "tcp/192.168.1.10:7447"
      namespace: fleet
```

### Cloud Connectivity

Connect to a Zenoh router for cloud/remote access:

```yaml
topics:
  - name: telemetry
    transport: zenoh
    zenoh:
      connect:
        - "tcp/cloud.example.com:7447"
      reliability: reliable
```

## Shared Memory (Default)

For same-machine communication, HORUS uses shared memory by default:

```rust,ignore
use horus::prelude::*;

// Default: shared memory transport (~85ns latency)
let topic = Topic::<SensorData>::new("sensor_data")?;
```

Shared memory topics are stored in `/dev/shm/horus/` and provide sub-microsecond latency with zero-copy semantics.

### Performance Characteristics

| Metric | Shared Memory | Zenoh (Local) | Zenoh (Network) |
|--------|--------------|---------------|-----------------|
| Latency | ~85ns | ~100μs | Network dependent |
| Throughput | Millions msg/s | High | Network dependent |
| Zero-copy | Yes | No | No |
| Cross-machine | No | Yes | Yes |

## Best Practices

### 1. Use Shared Memory for Local Communication

```yaml
# Don't use Zenoh for same-machine nodes
topics:
  - name: sensor_data
    # No transport specified = shared memory (fastest)
```

### 2. Use Zenoh Only When Needed

```yaml
# Multi-robot or cross-machine communication
topics:
  - name: fleet_status
    transport: zenoh
    zenoh:
      connect: ["tcp/192.168.1.100:7447"]
```

### 3. Enable Express Mode for Low Latency

```yaml
topics:
  - name: control_cmd
    transport: zenoh
    zenoh:
      express: true  # Skip batching
      priority: 7    # Highest priority
```

### 4. Use CDR Serialization for ROS2

```yaml
topics:
  - name: cmd_vel
    transport: zenoh
    zenoh:
      ros2_mode: true
      ros2_domain_id: 0
      serialization: cdr  # ROS2 wire format
```
