# Safety Monitor

The Safety Monitor provides real-time safety monitoring for safety-critical robotics applications. It enforces timing constraints, monitors node health, and applies deadline miss policies when safety violations occur.

## Overview

The Safety Monitor includes:
- **Watchdogs**: Monitor node liveness — trigger action if a critical node hangs
- **Budget Enforcement**: Per-node tick budgets — act if a node takes too long
- **Deadline Tracking**: Count deadline misses and apply the configured `Miss` policy
- **Miss Policies**: `Warn`, `Skip`, `SafeMode`, or `Stop` — per-node control over what happens on deadline miss

The Scheduler manages the safety monitor internally — you select a profile preset and the scheduler automatically feeds watchdogs, checks budgets, and applies miss policies.

## Enabling Safety Monitoring

Use profile presets to enable safety monitoring. Presets bundle the right combination of safety features:

```rust
use horus::prelude::*;

// Production: safety monitor + watchdog + blackbox
let mut scheduler = Scheduler::deploy()
    .tick_rate(1000.0.hz());

// Safety-critical: all RT + blackbox + profiling (panics without RT capabilities)
let mut scheduler = Scheduler::safety_critical()
    .tick_rate(1000.0.hz())
    .max_deadline_misses(3);
```

### Profile Preset Comparison

| Preset | Safety Monitor | Watchdog | Budget Enforcement | Memory Locking | Blackbox |
|--------|---------------|----------|-------------------|----------------|----------|
| `new()` | No | No | No | No | No |
| `deploy()` | **Yes** | **Yes** (500ms) | **Yes** | No | **Yes** (64MB) |
| `hard_rt()` | **Yes** | **Yes** (500ms) | **Yes** | **Yes** | No |
| `safety_critical()` | **Yes** | **Yes** (500ms) | **Yes** | **Yes** | **Yes** (64MB) |

## Configuring Nodes with Budgets

After selecting a preset, add nodes with timing constraints using the node builder. Setting `.budget_us()` automatically marks the node as RT — no separate `.rt()` call needed:

```rust
use horus::prelude::*;

let mut scheduler = Scheduler::deploy()
    .tick_rate(1000.0.hz());

// RT node with budget and deadline — budget_us auto-marks as RT
scheduler.add(motor_controller)
    .order(0)
    .budget_us(500)          // 500μs tick budget
    .deadline_us(1000)       // 1ms deadline
    .on_miss(Miss::SafeMode) // Enter safe state on miss
    .build()?;

scheduler.add(sensor_fusion)
    .order(1)
    .budget_us(2000)
    .deadline_us(5000)
    .on_miss(Miss::Skip)     // Skip tick on miss
    .build()?;

scheduler.run()?;
```

## Watchdogs

Watchdogs monitor node liveness. The scheduler automatically feeds watchdogs on successful node ticks. If a critical node fails to execute within the watchdog timeout, an emergency stop is triggered.

```
Normal operation:
  Node tick → success → watchdog fed → timer reset

Failure scenario:
  Node hangs → watchdog timeout expires → EMERGENCY STOP
```

### Timeout Guidelines

```
Watchdog timeout should be:
  - Longer than expected execution time
  - Shorter than safety-critical response time

Example:
  Expected tick period:  10ms
  Safety deadline:      100ms
  Watchdog timeout:      50ms  (5× period)
```

## Budget Enforcement

Per-node tick budgets ensure nodes complete within time limits. Set budgets via the node builder:

```rust
scheduler.add(motor_controller)
    .order(0)
    .budget_us(500)          // 500μs tick budget
    .deadline_us(1000)       // 1ms deadline
    .on_miss(Miss::SafeMode) // Enter safe state on budget/deadline miss
    .build()?;
```

When a node exceeds its budget, the configured `Miss` policy is applied. Violations are also recorded in the [BlackBox](/advanced/blackbox) when using `deploy()` or `safety_critical()` presets.

## Miss — Deadline Miss Policy

The `Miss` enum controls what happens when a node exceeds its deadline:

| Policy | Behavior |
|--------|----------|
| `Miss::Warn` | Log a warning and continue (default) |
| `Miss::Skip` | Skip the node for this tick |
| `Miss::SafeMode` | Call `enter_safe_state()` on the node |
| `Miss::Stop` | Stop the entire scheduler |

### SafeMode in Detail

When `Miss::SafeMode` triggers:
1. The scheduler calls `enter_safe_state()` on the offending node
2. Each subsequent tick, the scheduler checks `is_safe_state()`
3. When the node reports safe, normal operation resumes

Implement these on your Node:

```rust
impl Node for MotorController {
    fn enter_safe_state(&mut self) {
        self.velocity = 0.0;
        self.disable_motor();
    }

    fn is_safe_state(&self) -> bool {
        self.velocity == 0.0
    }

    fn tick(&mut self) { /* ... */ }
}
```

## Emergency Stop

Emergency stop is triggered automatically by:
- Watchdog expiration (node hangs)
- `Miss::Stop` policy on deadline miss
- Exceeding the `max_deadline_misses` threshold

When emergency stop triggers:
1. All node execution is halted
2. An emergency stop event is recorded in the BlackBox
3. The scheduler transitions to emergency state

### Inspecting After Emergency Stop

```rust,ignore
use horus::prelude::*;

let mut scheduler = Scheduler::deploy()
    .tick_rate(1000.0.hz());

// ... application runs and hits emergency stop ...

// Inspect what happened via BlackBox
if let Some(bb) = scheduler.blackbox() {
    let anomalies = bb.anomalies();
    println!("=== SAFETY EVENTS ({}) ===", anomalies.len());
    for record in &anomalies {
        println!("[tick {}] {:?}", record.tick, record.event);
    }
}
```

## Best Practices

### 1. Start with Conservative Budgets

Set generous budgets initially, then tighten after profiling:

```rust
// Start: 3× expected execution time
scheduler.add(motor_controller)
    .order(0)
    .budget_us(1500)         // 3× expected
    .on_miss(Miss::Warn)     // Log only while tuning
    .build()?;

// After profiling: 2× measured worst case
scheduler.add(motor_controller)
    .order(0)
    .budget_us(1000)         // 2× measured worst case
    .on_miss(Miss::SafeMode) // Enforce in production
    .build()?;
```

### 2. Layer Safety Checks

Use presets (watchdog + budget enforcement) with per-node miss policies:

```rust
// deploy() gives you watchdog + budget enforcement + blackbox
let mut scheduler = Scheduler::deploy()
    .tick_rate(1000.0.hz());

// Then set per-node policies for fine-grained control
scheduler.add(motor_controller)
    .order(0)
    .budget_us(500)
    .on_miss(Miss::SafeMode)  // Critical — enter safe state
    .build()?;

scheduler.add(telemetry)
    .order(10)
    .budget_us(5000)
    .on_miss(Miss::Skip)      // Non-critical — just skip
    .build()?;
```

### 3. Choose the Right Preset

| Use Case | Preset |
|----------|--------|
| Medical / surgical robots | `Scheduler::safety_critical()` |
| Industrial control | `Scheduler::hard_rt()` |
| CNC / aerospace | `Scheduler::safety_critical()` |
| General production | `Scheduler::deploy()` |

### 4. Test Safety Setup

Verify your system handles deadline misses correctly:

```rust,ignore
#[test]
fn test_safety_critical_setup() {
    let mut scheduler = Scheduler::deploy()
        .tick_rate(1000.0.hz());

    scheduler.add(test_node)
        .order(0)
        .budget_us(100)
        .on_miss(Miss::SafeMode)
        .build()
        .expect("should build node");
}
```
