# Safety Monitor

The Safety Monitor provides real-time safety monitoring for safety-critical robotics applications. It enforces timing constraints, monitors node health, and triggers emergency stops when safety violations occur.

## Overview

The Safety Monitor includes:
- **Watchdogs**: Monitor node liveness — trigger emergency stop if a critical node hangs
- **WCET Enforcement**: Worst-Case Execution Time budgets — halt if a node takes too long
- **Deadline Tracking**: Count deadline misses and trigger emergency stop at threshold
- **Emergency Stop**: Immediate system halt on critical failures

The Scheduler manages the safety monitor internally — you enable it via builder methods and the scheduler automatically feeds watchdogs, checks WCET, and triggers emergency stops.

## Enabling Safety Monitoring

Use builder methods on `Scheduler::new()` to enable safety monitoring:

```rust
use horus::prelude::*;

// Zero tolerance for deadline misses (surgical / medical)
let mut scheduler = Scheduler::new()
    .safety_monitor(true)
    .watchdog(Duration::from_millis(100))
    .memory_locked(true);

// Tolerates a few deadline misses (industrial / CNC)
let mut scheduler = Scheduler::new()
    .safety_monitor(true)
    .watchdog(Duration::from_millis(10))
    .memory_locked(true);
```

### Safety Builder Methods

| Method | Description | Example |
|--------|-------------|---------|
| `.safety_monitor(true)` | Enable safety monitoring | `.safety_monitor(true)` |
| `.watchdog(duration)` | Set watchdog timeout | `.watchdog(Duration::from_millis(100))` |
| `.memory_locked(true)` | Enable `mlockall()` | `.memory_locked(true)` |
| `.rt_scheduling(true)` | Enable RT scheduling (SCHED_FIFO) | `.rt_scheduling(true)` |

## Configuring Critical Nodes

After configuring the scheduler, register critical nodes with timing constraints using the node builder:

```rust,ignore
use horus::prelude::*;
use std::time::Duration;

let mut scheduler = Scheduler::new()
    .safety_monitor(true);

// RT node with WCET budget and deadline
scheduler.add(motor_controller)
    .order(0)
    .rt()
    .wcet_us(500)       // 500μs max execution time
    .deadline_us(1000)   // 1ms deadline
    .done();

scheduler.add(sensor_fusion)
    .order(1)
    .rt()
    .wcet_us(2000)
    .deadline_us(5000)
    .done();

// Register critical nodes with watchdog timeouts
scheduler.add_critical_node("motor_controller", Duration::from_millis(50))?;
scheduler.add_critical_node("sensor_fusion", Duration::from_millis(100))?;

// Set WCET budgets
scheduler.set_wcet_budget("motor_controller", Duration::from_micros(500))?;
scheduler.set_wcet_budget("sensor_fusion", Duration::from_micros(2000))?;

scheduler.run()?;
```

## Watchdogs

Watchdogs monitor node liveness. The scheduler automatically feeds watchdogs on successful node ticks. If a critical node fails to execute within the watchdog timeout, an emergency stop is triggered.

```
Normal operation:
  Node tick → success → watchdog fed → timer reset

Failure scenario:
  Node hangs → watchdog timeout expires → EMERGENCY STOP
```

### Timeout Guidelines

```
Watchdog timeout should be:
  - Longer than expected execution time
  - Shorter than safety-critical response time

Example:
  Expected tick period:  10ms
  Safety deadline:      100ms
  Watchdog timeout:      50ms  (5× period)
```

## WCET Enforcement

Worst-Case Execution Time (WCET) budgets ensure nodes complete within time limits. Set budgets via the node builder:

```rust,ignore
scheduler.add(motor_controller)
    .order(0)
    .rt()
    .wcet_us(500)      // 500μs max execution time
    .deadline_us(1000)  // 1ms deadline
    .done();
```

For critical nodes, WCET violations trigger an emergency stop. For non-critical nodes, violations are logged and recorded in the [BlackBox](/advanced/blackbox).

## Emergency Stop

Emergency stop is triggered automatically by:
- Critical node watchdog expiration
- Critical node WCET violation
- Critical node deadline miss
- Exceeding the `max_deadline_misses` threshold

When emergency stop triggers:
1. All node execution is halted
2. An emergency stop event is recorded in the BlackBox
3. The scheduler transitions to emergency state

### Inspecting After Emergency Stop

```rust,ignore
use horus::prelude::*;

let mut scheduler = Scheduler::new()
    .safety_monitor(true);

// ... application runs and hits emergency stop ...

// Inspect what happened via BlackBox
if let Some(bb) = scheduler.blackbox() {
    let anomalies = bb.anomalies();
    println!("=== SAFETY EVENTS ({}) ===", anomalies.len());
    for record in &anomalies {
        println!("[tick {}] {:?}", record.tick, record.event);
    }
}
```

## Best Practices

### 1. Start with Conservative Budgets

Set generous WCET budgets initially, then tighten after profiling:

```rust,ignore
// Start: 3× expected execution time
scheduler.set_wcet_budget("motor", Duration::from_micros(1500))?;

// After profiling: 2× measured worst case
scheduler.set_wcet_budget("motor", Duration::from_micros(1000))?;
```

### 2. Layer Safety Checks

Use watchdogs (liveness) and WCET budgets (timing) together:

```rust,ignore
// Both work together to catch different failure modes
scheduler.add_critical_node("motor", Duration::from_millis(50))?;  // Liveness
scheduler.set_wcet_budget("motor", Duration::from_micros(500))?;   // Timing
```

### 3. Choose the Right Configuration

| Use Case | Configuration |
|----------|---------------|
| Medical / surgical robots | `Scheduler::new().safety_monitor(true)` |
| Industrial control | `Scheduler::new().safety_monitor(true)` |
| CNC / aerospace | `Scheduler::new().safety_monitor(true)` |
| General production | `Scheduler::new()` + per-node `.rt()` / `.compute()` |

### 4. Test Emergency Stop

Verify your system handles emergency stop correctly:

```rust,ignore
#[test]
fn test_safety_critical_setup() {
    let mut scheduler = Scheduler::new()
        .safety_monitor(true);

    scheduler.add(test_node)
        .order(0)
        .rt()
        .wcet_us(100)
        .done();

    scheduler.add_critical_node("test_node", Duration::from_millis(10))
        .expect("should register critical node");
}
```
