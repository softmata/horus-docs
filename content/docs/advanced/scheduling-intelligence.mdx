# Scheduling Intelligence

## Why Tiers Exist

Different nodes have different execution time characteristics:

| Node Type | Example | Typical Execution | Tier |
|-----------|---------|-------------------|------|
| Fast math | PID controller | &lt;1μs | **UltraFast** |
| Sensors | Camera reader, IMU | &lt;10μs | **Fast** |
| Algorithms | Path planner | &lt;100μs+ | **Normal** |

Tiers let you declare a node's execution characteristics so the scheduler can make informed decisions about failure policies and execution strategy.

## Node Tier Annotation

Use `NodeTier` to explicitly declare a node's execution characteristics:

```rust,ignore
use horus::prelude::*;

let mut scheduler = Scheduler::new();

// Annotate nodes with their tier
scheduler.add(pid_node).order(0).tier(NodeTier::UltraFast).done();
scheduler.add(sensor_node).order(1).tier(NodeTier::Fast).done();
scheduler.add(planner_node).order(2).tier(NodeTier::Normal).done();

scheduler.run()?;
```

### Available Tiers

| Tier | Use For | Description | Default Failure Policy |
|------|---------|-------------|----------------------|
| `NodeTier::UltraFast` | Ultra-fast math (&lt;1μs) | Highest-priority inline execution | Fatal (stop on failure) |
| `NodeTier::Fast` | Sensors, filters (&lt;10μs) | Inline execution (default tier) | Fatal |
| `NodeTier::Normal` | Algorithms (&lt;100μs+) | Standard scheduling | Restart (5 attempts, 100ms delay) |

### Tier Descriptions

```rust,ignore
// Get human-readable description
let tier = NodeTier::UltraFast;
println!("{}", tier.description());
// Output: "Ultra-fast inline (<1us)"

let tier = NodeTier::Fast;
println!("{}", tier.description());
// Output: "Inline execution (<10us)"

let tier = NodeTier::Normal;
println!("{}", tier.description());
// Output: "Standard scheduling (<100us+)"
```

### Default Failure Policies

Each tier has a default failure policy that can be overridden:

```rust,ignore
use horus::prelude::*;

// UltraFast and Fast tiers default to Fatal - the system stops if they fail
scheduler.add(critical_pid)
    .tier(NodeTier::UltraFast)
    .done();

// Normal tier defaults to Restart with 5 attempts and 100ms delay
scheduler.add(planner)
    .tier(NodeTier::Normal)
    .done();
```

## Best Practices

### 1. Start Simple

Most nodes work fine without tier annotations (defaults to `Fast`):

```rust,ignore
// Good: Let HORUS use the default tier
scheduler.add(my_node).done();

// Only annotate when you have specific performance needs
scheduler.add(critical_pid).tier(NodeTier::UltraFast).done();
```

### 2. Match Tier to Actual Performance

Choose tiers based on measured execution time:

```rust,ignore
// <1μs: Simple math, PID loops, state checks
scheduler.add(pid_node).tier(NodeTier::UltraFast).done();

// <10μs: Sensor reading, filtering, encoding
scheduler.add(sensor_node).tier(NodeTier::Fast).done();

// >10μs: Path planning, ML inference, file I/O
scheduler.add(planner_node).tier(NodeTier::Normal).done();
```

### 3. Use Tiers for Deterministic Execution

Tiers are explicit annotations — no runtime profiling needed, so execution is fully deterministic. This makes them ideal for [deterministic execution](/advanced/deterministic-execution) scenarios.
