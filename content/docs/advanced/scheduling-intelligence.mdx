# Scheduling Intelligence

## Why Tiers Exist

Different nodes have different needs:

| Node Type | Example | Problem | Solution (Tier) |
|-----------|---------|---------|-----------------|
| Fast math | PID controller | Overhead from function calls | **UltraFast**: Highest-priority inline execution |
| Blocking I/O | Camera reader | Blocks the scheduler | **AsyncIO**: Annotate for I/O awareness |
| Normal | Most nodes | None | **Fast**: Inline execution |

Tiers let you declare a node's execution characteristics so the scheduler can make informed decisions.

## Node Tier Annotation

Use `NodeTier` to explicitly declare a node's execution characteristics:

```rust
use horus::prelude::*;

let mut scheduler = Scheduler::new();

// Annotate nodes with their tier
scheduler.add(pid_node).order(0).tier(NodeTier::UltraFast).done();
scheduler.add(sensor_node).order(1).tier(NodeTier::Fast).done();
scheduler.add(logger_node).order(5).tier(NodeTier::Background).done();

scheduler.run();
```

### Available Tiers

| Tier | Use For | Description |
|------|---------|-------------|
| `NodeTier::UltraFast` | Ultra-fast math (\<1us) | Inline execution (highest priority) |
| `NodeTier::Fast` | Sensors, filters (\<10us) | Inline execution |
| `NodeTier::Normal` | Algorithms (\<100us) | Standard scheduling |
| `NodeTier::AsyncIO` | Network, file I/O | I/O-bound operations |
| `NodeTier::Background` | Logging, diagnostics | Low-priority operations |
| `NodeTier::Auto` | Let system decide | Based on profile data |

### Tier Descriptions

```rust
// Get human-readable description
let tier = NodeTier::UltraFast;
println!("{}", tier.description());
// Output: "Ultra-fast inline (<1us)"
```

## Offline Profiling

Profile your system once in a controlled environment, then use the results in production for deterministic startup:

### Creating Profiles

```rust
use horus::prelude::*;
use std::time::Instant;

// Create offline profiler with name and target tick count
let mut profiler = OfflineProfiler::new("robot_profile", 100);

// Profile each node by recording execution times
for _ in 0..100 {
    let start = Instant::now();
    sensor_node.tick();
    profiler.record("sensor", start.elapsed());

    let start = Instant::now();
    filter_node.tick();
    profiler.record("filter", start.elapsed());

    profiler.tick();
}

// Finalize and save profile for production use
let profile = profiler.finalize();
profile.save("profiles/robot.bin")?;

// Or save as human-readable JSON
profile.save_json("profiles/robot.json")?;
```

### Loading Profiles

```rust
use horus::prelude::*;

// Load pre-computed profile (auto-detects binary or JSON format)
let profile = ProfileData::load("profiles/robot.bin")?;

// Use profile data to set explicit tiers on nodes
let mut scheduler = Scheduler::new();
scheduler.add(sensor_node).tier(profile.get_tier("sensor")).done();
scheduler.add(filter_node).tier(profile.get_tier("filter")).done();

// Nodes now use profiled tiers - deterministic startup
scheduler.run();
```

## Best Practices

### 1. Start Simple

Most nodes work fine without tier annotations:

```rust
// Good: Let HORUS use defaults
scheduler.add(my_node).done();

// Only annotate when you have specific performance needs
scheduler.add(critical_pid).tier(NodeTier::UltraFast).done();
```

### 2. Use Offline Profiles for Production

```rust
// Development: Profile your nodes
let mut profiler = OfflineProfiler::new("production", 100);
// ... record execution times ...
let profile = profiler.finalize();
profile.save("production.bin")?;

// Production: Load saved profile
let profile = ProfileData::load("production.bin")?;
let mut scheduler = Scheduler::new();
scheduler.add(node1).tier(profile.get_tier("node1")).done();
// Deterministic startup with optimized tiers
```

### 3. Inspect Profile Results

```rust
let profile = profiler.finalize();
profile.print_summary();
// Shows each node's tier, average execution time, and characteristics
```
