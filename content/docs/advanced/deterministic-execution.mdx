# Deterministic Execution

HORUS supports deterministic execution where the same inputs produce identical outputs every run. This is useful for debugging, regression testing, and safety-critical systems.

## Why Determinism Matters

**Debugging**: Non-deterministic bugs are hard to reproduce. Deterministic mode lets you replay exact sequences.

**Testing**: Repeatable unit tests and regression testing require the same outputs for the same inputs.

**Safety Certification**: Standards like ISO 26262 and IEC 62443 require predictable execution timing and reproducible behavior.

## Determinism Levels

HORUS offers different levels of deterministic guarantees:

| Level | Config | What You Get | Use Case |
|-------|--------|--------------|----------|
| **Basic** | `Scheduler::new()` | Sequential execution, no learning | Most applications |
| **+ Performance** | `.tier(NodeTier::*)` | Basic + explicit optimization tiers | Speed + determinism |
| **+ Safety** | `SchedulerConfig::safety_critical()` | Basic + watchdogs, WCET enforcement | Medical, industrial |
| **+ Full** | `SchedulerConfig::deterministic()` | Virtual time, seeded RNG, execution tracing | Formal verification |

### Level 1: Basic Determinism (Default)

`Scheduler::new()` is deterministic out of the box:

```rust,ignore
use horus::prelude::*;

fn main() -> Result<()> {
    let mut scheduler = Scheduler::new();
    scheduler.add(my_node).order(0).done();
    scheduler.run()?;
    Ok(())
}
```

**Guarantees:**
- Sequential execution (same order every tick)
- No learning phase (no runtime profiling)
- Reproducible runs with same inputs

### Level 2: Determinism + Performance Tiers

Use `.tier()` to get deterministic execution with explicit performance tiers:

```rust,ignore
use horus::prelude::*;

let mut scheduler = Scheduler::new();

scheduler.add(pid_controller).order(0).tier(NodeTier::UltraFast).done();  // <1μs inline
scheduler.add(sensor_reader).order(1).tier(NodeTier::Fast).done();        // <10μs inline
scheduler.add(data_logger).order(5).tier(NodeTier::Normal).done();        // Standard scheduling

scheduler.run()?;
```

**Node tiers:**

| Tier | Description | Default Failure Policy |
|------|-------------|----------------------|
| `NodeTier::UltraFast` | Ultra-fast inline (<1μs) | Fatal (stop on failure) |
| `NodeTier::Fast` | Inline execution (<10μs) | Fatal |
| `NodeTier::Normal` | Standard scheduling (<100μs+) | Restart (5 attempts, 100ms delay) |

Tiers are explicit — no runtime profiling needed, so execution is fully deterministic.

### Level 3: Determinism + Safety

Use `SchedulerConfig::safety_critical()` for safety-critical systems:

```rust,ignore
use horus::prelude::*;

let scheduler = Scheduler::new()
    .with_config(SchedulerConfig::safety_critical());
```

**Adds:**
- Watchdog timers
- WCET enforcement
- Deadline monitoring
- Memory locking (mlockall)
- Real-time scheduling class (SCHED_FIFO)

### Level 4: Full Deterministic Mode

Use `SchedulerConfig::deterministic()` for full reproducibility with virtual time:

```rust,ignore
use horus::prelude::*;

let scheduler = Scheduler::new()
    .with_config(SchedulerConfig::deterministic());
```

**Adds:**
- Virtual time (deterministic clock instead of wall clock)
- Seeded RNG (all randomness derived from seed)
- Execution tracing (record/replay exact node sequences)
- Static execution order

## DeterministicConfig

The `DeterministicConfig` controls virtual time and tracing:

```rust
pub struct DeterministicConfig {
    /// Seed for deterministic RNG (default: 42)
    pub seed: u64,
    /// Use virtual time instead of wall clock (default: true)
    pub virtual_time: bool,
    /// Fixed tick duration in nanoseconds (default: 1_000_000 = 1ms)
    pub tick_duration_ns: u64,
    /// Record execution trace for comparison (default: true)
    pub record_trace: bool,
}
```

```rust,ignore
// Default config
let config = DeterministicConfig::default();
// seed: 42, virtual_time: true, tick_duration_ns: 1_000_000, record_trace: true

// Custom config with tracing
let config = DeterministicConfig::with_trace(123); // Custom seed
```

## Deterministic Clock

The `DeterministicClock` provides reproducible time that advances in fixed steps:

```rust,ignore
use horus::prelude::*;

let config = DeterministicConfig::default();
let clock = DeterministicClock::new(&config);

// Virtual time starts at 0
assert_eq!(clock.now_ns(), 0);
assert_eq!(clock.tick(), 0);

// Advance one tick (adds tick_duration_ns)
clock.advance_tick();
assert_eq!(clock.tick(), 1);
assert_eq!(clock.now_ns(), 1_000_000); // 1ms

// Deterministic random numbers (same seed = same sequence)
let r1 = clock.random_u64();
let r2 = clock.random_u64();

// Reset to initial state
clock.reset();
assert_eq!(clock.tick(), 0);
```

Two clocks with the same seed produce identical random sequences — useful for verifying determinism.

## Execution Tracing

Record and compare execution traces to detect non-determinism:

```rust,ignore
use horus::prelude::*;

let config = DeterministicConfig::with_trace(42);

// Run 1
let mut trace1 = ExecutionTrace::new(config.clone());
// ... trace entries added by scheduler during execution ...

// Run 2
let mut trace2 = ExecutionTrace::new(config);
// ... trace entries added by scheduler during execution ...

// Compare the two runs
match trace1.compare(&trace2) {
    None => println!("Runs are identical!"),
    Some(divergence) => {
        println!("Diverged at tick {}: {}", divergence.tick, divergence.message);
    }
}

// Save/load traces for later comparison
trace1.save(Path::new("trace_run1.json"))?;
let loaded = ExecutionTrace::load(Path::new("trace_run1.json"))?;
```

Each trace entry records:
- Tick number and node index
- Entry type (TickStart, TickEnd, Input, Output, StateChange, Error, Custom)
- Timestamp and duration
- Input/output hashes for comparison

## WCET Timing Analysis

The `TimingBounds` system tracks execution timing for WCET (Worst-Case Execution Time) verification:

```rust,ignore
use horus::prelude::*;

let mut bounds = TimingBounds::new(1000); // 1ms WCET budget

// Record per-node execution times
bounds.record_node_execution("sensor", tick, 200_000);  // 200μs - OK
bounds.record_node_execution("control", tick, 1_500_000); // 1.5ms - VIOLATION!

// Check compliance
match bounds.check_compliance() {
    Ok(()) => println!("All executions within WCET"),
    Err(e) => println!("WCET violation: {}", e),
}

// Inspect violations
for v in &bounds.violations {
    println!("[tick {}] {}: expected <{}μs, actual {}ns (severity: {:?})",
        v.tick, v.node_name, v.expected_us, v.actual_ns, v.severity);
}
```

Violation severities:
| Severity | Threshold |
|----------|-----------|
| `Minor` | <10% over WCET |
| `Major` | 10-50% over WCET |
| `Critical` | >50% over WCET |

## Deterministic vs Non-Deterministic

**Default (Sequential, Deterministic):**
```
Run 1: Node A → Node B → Node C
Run 2: Node A → Node B → Node C  (identical)
Run 3: Node A → Node B → Node C  (identical)
```

**Parallel Mode (Non-Deterministic):**
```
Run 1: Node A → Node B → Node C
Run 2: Node B → Node A → Node C  (thread scheduling varies)
```

| Metric | Sequential (Deterministic) | Parallel |
|--------|---------------------------|----------|
| Consistency | Perfect | Variable |
| Multi-core | No | Yes |
| Certification Ready | Yes | No |

## Best Practices

### Use Deterministic Seeds

For any randomness in your nodes:

```rust,ignore
impl Node for RandomNode {
    fn init(&mut self) -> Result<()> {
        self.rng = StdRng::seed_from_u64(42);
        Ok(())
    }

    fn tick(&mut self) {
        // Generates same sequence every run
        let value = self.rng.gen::<f64>();
    }
}
```

### Avoid System Time

```rust,ignore
// BAD: Non-deterministic
fn tick(&mut self) {
    let now = std::time::Instant::now();  // Different every run
}

// GOOD: Use internal state counter
fn tick(&mut self) {
    self.tick_count += 1;  // Same sequence every run
}
```

### Control External Inputs

```rust,ignore
// For testing, mock external sensors
#[cfg(test)]
impl Node for SensorNode {
    fn tick(&mut self) {
        self.output = self.test_data[self.tick_count % self.test_data.len()];
    }
}
```
