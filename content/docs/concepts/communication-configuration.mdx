# Communication Configuration

Managing endpoints through configuration files makes your code environment-agnostic and easier to deploy across development, staging, and production environments.

## Why Use Configuration Files?

**Without configuration** (hardcoded):
```rust
// Development machine
let topic: Topic<Status> = Topic::new("status")?;  // Local

// Production robot
let topic: Topic<Status> = Topic::new("status@192.168.1.100")?;  // Network
// Need to change code for different environments!
```

**With configuration** (environment-agnostic):
```rust
// Same code for dev and production!
let topic: Topic<Status> = Topic::from_config("status")?;
// Endpoint loaded from config file
```

## Configuration File Format

HORUS uses YAML for configuration:

**horus.yaml**:
```yaml
topics:
  telemetry:
    name: telemetry
    endpoint: telemetry@192.168.1.100:8000

  camera:
    name: camera
    endpoint: camera@192.168.1.50:9000

  motors:
    name: motors
    endpoint: motors  # Local shared memory
```

## Configuration Search Path

HORUS searches for configuration files in this order:

1. `./horus.yaml` (current directory)
2. `~/.horus/config.yaml` (user home)
3. `/etc/horus/config.yaml` (system-wide)

**Priority**: Files earlier in the search path override later ones.

## Loading from Configuration

### Topic from Config

```rust
use horus::prelude::*;

// Load from default search path
let telemetry: Topic<Status> = Topic::from_config("telemetry")?;

// Load from specific file
let camera: Topic<Image> = Topic::from_config_file("my_config.yaml", "camera")?;
```

### Topic from Config

```rust
use horus::prelude::*;

// Producer
let output: Topic<SensorData> = Topic::from_config("sensors")?;

// Consumer
let input: Topic<SensorData> = Topic::from_config("sensors")?;

// From specific file
let motors: Topic<MotorCmd> = Topic::from_config_file(
    "/etc/robot/config.toml",
    "motors"
)?;
```

### Development Environment

**horus_dev.yaml**:
```yaml
# Local shared memory for development
topics:
  telemetry:
    name: telemetry
    endpoint: telemetry  # Local

  camera:
    name: camera
    endpoint: camera  # Local

  motors:
    name: motors
    endpoint: motors  # Local
```

### Production Environment

**horus_prod.yaml**:
```yaml
# Network endpoints for production
topics:
  telemetry:
    name: telemetry
    endpoint: telemetry@ground-station:8000

  camera:
    name: camera
    endpoint: camera@edge-device.local:9000

  motors:
    name: motors
    endpoint: motors  # Still local (critical path)
```

### Switching Environments

**Method 1: Symlink**
```bash
# Development
ln -sf horus_dev.yaml horus.yaml

# Production
ln -sf horus_prod.yaml horus.yaml
```

**Method 2: Environment Variable**
```rust
use horus::prelude::*;

let config_file = std::env::var("HORUS_CONFIG")
    .unwrap_or_else(|_| "horus.yaml".to_string());

let telemetry: Topic<Status> = Topic::from_config_file(&config_file, "telemetry")?;
```

```bash
# Development
export HORUS_CONFIG=horus_dev.yaml
horus run robot.rs

# Production
export HORUS_CONFIG=horus_prod.yaml
horus run --release robot.rs
```

## Complete Example

### Configuration File

**horus.yaml**:
```yaml
# ======= ROBOT CONFIGURATION =======
topics:
  # Network telemetry to ground station
  telemetry:
    name: telemetry
    endpoint: telemetry@192.168.1.100:8000

  # Network camera to processing server
  camera:
    name: camera
    endpoint: camera@192.168.1.200:9000

  # Local motor control (critical path - must be local!)
  motors:
    name: motors
    endpoint: motors

  # Local IMU (critical path)
  imu:
    name: imu
    endpoint: imu

  # Network fleet coordination
  fleet:
    name: fleet
    endpoint: fleet@router:7000
```

### Application Code

```rust
use horus::prelude::*;

struct Robot {
    // Network: telemetry to ground station
    telemetry: Topic<Status>,

    // Network: camera to processing server
    camera: Topic<Image>,

    // Local: critical control loop
    imu: Topic<ImuData>,
    motors: Topic<MotorCmd>,

    // Network: fleet coordination
    fleet: Topic<FleetMsg>,
}

impl Robot {
    fn new() -> Result<Self> {
        Ok(Self {
            // All loaded from config - no hardcoded endpoints!
            telemetry: Topic::from_config("telemetry")?,
            camera: Topic::from_config("camera")?,
            imu: Topic::from_config("imu")?,
            motors: Topic::from_config("motors")?,
            fleet: Topic::from_config("fleet")?,
        })
    }
}
```

## Advanced Configuration

### Per-Environment Overrides

**horus.yaml** (base config):
```yaml
topics:
  telemetry:
    name: telemetry
    endpoint: telemetry@ground-station:8000
```

**horus_local.yaml** (local override):
```yaml
topics:
  telemetry:
    name: telemetry
    endpoint: telemetry  # Override to local for testing
```

```rust
// Load with fallback
let config_file = if cfg!(debug_assertions) {
    "horus_local.yaml"
} else {
    "horus.yaml"
};

let telemetry: Topic<Status> = Topic::from_config_file(config_file, "telemetry")?;
```

## Configuration Management Best Practices

### 1. Version Control

```bash
# Track all config files
git add horus*.yaml
git commit -m "Add robot configuration files"

# .gitignore sensitive production configs
echo "horus_prod_secrets.yaml" >> .gitignore
```

### 2. Environment Templates

**horus.template.yaml**:
```yaml
# Template configuration - copy and customize
topics:
  telemetry:
    name: telemetry
    endpoint: telemetry@GROUND_STATION_IP:8000

  camera:
    name: camera
    endpoint: camera@EDGE_DEVICE_IP:9000
```

```bash
# Setup new deployment
cp horus.template.yaml horus.yaml
# Edit horus.yaml with actual IPs
```

### 3. Deployment Scripts

**deploy.sh**:
```bash
#!/bin/bash
# Deploy robot configuration

ROBOT_IP=$1
CONFIG_ENV=$2

if [ -z "$ROBOT_IP" ] || [ -z "$CONFIG_ENV" ]; then
    echo "Usage: ./deploy.sh <robot_ip> <dev|staging|prod>"
    exit 1
fi

# Copy environment-specific config
scp "horus_${CONFIG_ENV}.yaml" "robot@${ROBOT_IP}:/etc/horus/horus.yaml"

# Deploy and run
ssh "robot@${ROBOT_IP}" 'systemctl restart horus-robot'

echo "Deployed $CONFIG_ENV config to $ROBOT_IP"
```

```bash
# Deploy to staging
./deploy.sh 192.168.1.50 staging

# Deploy to production
./deploy.sh 192.168.1.50 prod
```

### 4. Configuration Validation

```rust
use horus::prelude::*;

fn validate_config() -> Result<()> {
    // Try loading all configured topics
    let _telemetry: Topic<Status> = Topic::from_config("telemetry")?;
    let _camera: Topic<Image> = Topic::from_config("camera")?;
    let _motors: Topic<MotorCmd> = Topic::from_config("motors")?;

    println!("[OK] Configuration valid");
    Ok(())
}

fn main() {
    if let Err(e) = validate_config() {
        eprintln!("[ERROR] Configuration error: {}", e);
        std::process::exit(1);
    }

    // Run application
}
```

## Troubleshooting

### Config File Not Found

**Error**: `Failed to load configuration: file not found`

**Solution**:
```bash
# Check current directory
ls -la horus.yaml

# Check user config
ls -la ~/.horus/config.yaml

# Check system config
ls -la /etc/horus/config.yaml

# Create config
cp horus.template.yaml horus.yaml
```

### Topic Not Found in Config

**Error**: `Topic 'telemetry' not found in configuration`

**Solution**:
```bash
# Verify topic name matches config
grep -A2 "telemetry:" horus.yaml

# Check YAML syntax
yamllint horus.yaml
```

### Invalid Endpoint Syntax

**Error**: `Invalid endpoint: telemetry@invalid:port`

**Solution**:
```yaml
# Correct endpoint formats
endpoint: topic                      # Local
endpoint: topic@192.168.1.100       # Network (default port)
endpoint: topic@192.168.1.100:8000  # Network (custom port)
endpoint: topic@hostname.local:9000  # Hostname
```

## Summary

**Benefits of Configuration Files**:
- Environment-agnostic code
- Easy deployment across dev/staging/prod
- No hardcoded IP addresses
- Centralized endpoint management
- Version controllable

**Best Practices**:
- Use configuration files for all endpoints
- Separate dev/staging/prod configs
- Version control configuration templates
- Validate configs before deployment
- Keep critical paths local (motors, IMU)

**File Locations**:
1. `./horus.yaml` (project-specific)
2. `~/.horus/config.yaml` (user-specific)
3. `/etc/horus/config.yaml` (system-wide)
