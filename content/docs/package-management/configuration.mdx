# Configuration Reference

Complete guide to configuring HORUS projects via `horus.toml` and understanding the auto-managed `.horus/` directory.

## Quick Reference

**Minimal `horus.toml`:**
```toml
[package]
name = "my_robot"
version = "0.1.0"

[dependencies]
horus = "*"
```

**Full `horus.toml`:**
```toml
[package]
name = "my_robot_controller"
version = "1.2.3"
description = "Advanced mobile robot controller with navigation"
author = "Robotics Team"
license = "Apache-2.0"
mode = "release"
language = "rust"
edition = "1"  # manifest schema version, defaults to "1"

[dependencies]
horus = "*"
serde = { version = "1", features = ["derive"] }
tokio = { version = "1", features = ["full"] }

[dev-dependencies]
proptest = "^1.4"

[build-dependencies]
cc = "^1.0"

[ignore]
files = ["debug_*.rs", "**/temp/**"]
directories = ["experiments/", "old/"]
packages = ["ipython", "jupyter"]
```

## Project Metadata

All project metadata fields live under the `[package]` table.

### `name` (Required)

Project name used for identification and package management.

**Type**: String
**Required**: Yes
**Constraints**:
- Must be unique within your organization
- Use lowercase with hyphens (kebab-case)
- No spaces or special characters except hyphens and underscores

**Examples:**
```toml
[package]
name = "temperature-monitor"
# or
name = "mobile_robot_controller"
# or
name = "warehouse-navigation"
```

### `version` (Required)

Project version following semantic versioning.

**Type**: String
**Required**: Yes
**Format**: `MAJOR.MINOR.PATCH` (semantic versioning)

**Examples:**
```toml
[package]
version = "0.1.0"    # Initial development
# or
version = "1.0.0"    # First stable release
# or
version = "2.3.1"    # Mature project
```

### `edition` (Optional)

Manifest schema version. Controls which fields and features are available in `horus.toml`.

**Type**: String
**Required**: No
**Default**: `"1"`

**Examples:**
```toml
[package]
edition = "1"
```

### `description` (Optional)

Human-readable description of your project.

**Type**: String
**Required**: No
**Default**: None

**Examples:**
```toml
[package]
description = "Temperature monitoring system with alerts"
# or
description = "Autonomous mobile robot for warehouse operations"
```

### `author` (Optional)

Project author or team name.

**Type**: String
**Required**: No
**Default**: None

**Examples:**
```toml
[package]
author = "Robotics Team"
# or
author = "John Doe <john@example.com>"
# or
author = "ACME Robotics Inc."
```

### `license` (Optional)

Project license identifier.

**Type**: String
**Required**: No
**Default**: None
**Common Values**: `Apache-2.0`, `MIT`, `GPL-3.0`, `BSD-3-Clause`

**Examples:**
```toml
[package]
license = "Apache-2.0"
# or
license = "MIT"
# or
license = "Proprietary"
```

## Build Configuration

Build configuration fields also live under `[package]`.

### `mode` (Optional)

Build mode for compilation.

**Type**: String
**Required**: No
**Default**: `debug`
**Values**: `debug`, `release`

**Examples:**
```toml
[package]
mode = "debug"    # Fast compilation, slower runtime
# or
mode = "release"  # Slower compilation, optimized runtime
```

**Override via CLI:**
```bash
horus run --release  # Overrides mode in horus.toml
```

### `language` (Optional)

Programming language for the project.

**Type**: String
**Required**: No
**Default**: Auto-detected from file extensions
**Values**: `rust`, `python`

**Examples:**
```toml
[package]
language = "rust"
# or
language = "python"
```

**Auto-detection:**
- `main.rs`  Rust
- `main.py`  Python

## Dependencies

Dependencies are declared in the `[dependencies]` table of `horus.toml`. HORUS supports multiple package sources:

| Source | Syntax | Example | Installed via |
|--------|--------|---------|---------------|
| **HORUS Registry** | `name = "version"` | `pid-controller = "^1.0"` | `horus install` or `horus run` |
| **crates.io** | `name = "version"` or inline table with `source` | `serde = "1"` | Auto-detected or explicit |
| **PyPI** | `name = { version = "...", source = "pypi" }` | `numpy = { version = "^1.24", source = "pypi" }` | Auto-detected or explicit |
| **Git** | Inline table with `git` field | See below | `horus run` (clones automatically) |
| **Local Path** | Inline table with `path` field | `my_driver = { path = "../driver" }` | `horus run` |

### Basic Dependencies

**Simple version string:**
```toml
[dependencies]
horus = "*"              # Latest from HORUS registry
serde = "1.0"            # Auto-detected: crates.io (Rust) or PyPI (Python)
numpy = "*"              # Auto-detected: PyPI
```

**Inline table with version and features:**
```toml
[dependencies]
horus = "*"
serde = { version = "1.0", features = ["derive"] }
tokio = { version = "1", features = ["full", "rt-multi-thread"] }
```

### Prefixed Dependencies (Custom Drivers)

For explicit control over where packages come from, use the `source` field:

**Cargo (crates.io):**
```toml
[dependencies]
rppal = { version = "0.14", source = "cargo" }                        # Raspberry Pi GPIO
tokio-serial = { version = "5.4", source = "cargo" }                  # Serial port
serde = { version = "1.0", source = "cargo", features = ["derive"] }  # With features
tokio = { version = "1", source = "cargo", features = ["full", "macros"] }
```

**Pip (PyPI):**
```toml
[dependencies]
numpy = { version = "^1.24", source = "pypi" }           # NumPy
opencv-python = { version = "^4.8", source = "pypi" }    # OpenCV
pyserial = { version = "^3.5", source = "pypi" }         # Serial port
```

**Local path (custom driver):**
```toml
[dependencies]
my_driver = { path = "../drivers/my_custom_driver" }
sensor_lib = { path = "./libs/sensor_lib" }
```

**Git repository:**
```toml
[dependencies]
# Basic git dependency
my_package = { git = "https://github.com/user/repo.git" }

# With specific branch
my_driver = { git = "https://github.com/user/driver.git", branch = "develop" }

# With specific tag
sensors = { git = "https://github.com/robotics/sensors.git", tag = "v1.2.0" }

# With specific commit
utils = { git = "https://github.com/user/utils.git", rev = "a1b2c3d4" }
```

### Dependency Fields

**`version`** (optional):
- Semantic version or version constraint
- Examples: `"1.0"`, `"^1.2"`, `">=1.0,<2.0"`, `"*"` (any)

**`features`** (optional):
- Array of feature flags to enable
- Rust-specific (Cargo features)

**`source`** (optional):
- Explicit package source: `"cargo"`, `"pypi"`, `"horus"`
- When omitted, HORUS auto-detects the source

**`path`** (optional):
- Local filesystem path to a crate/package

**`git`** (optional):
- Git repository URL for the package
- Must be a valid git URL (HTTPS or SSH)
- Cloned to `~/.horus/cache/git_*` on first use

**`branch`** (optional, with git):
- Specific branch to checkout
- Example: `branch = "develop"`

**`tag`** (optional, with git):
- Specific tag to checkout
- Example: `tag = "v1.0.0"`

**`rev`** (optional, with git):
- Specific commit SHA to checkout
- Example: `rev = "a1b2c3d4"`

**Resolution Order:**
1. HORUS registry (`https://marketplace.horus-registry.dev`)
2. Language-specific registry (crates.io for Rust, PyPI for Python)

### Dev and Build Dependencies

In addition to `[dependencies]`, you can declare dependencies that are only needed during development or at build time:

**`[dev-dependencies]`** - Only installed during development and testing:
```toml
[dev-dependencies]
proptest = "^1.4"
criterion = "^0.5"
mockall = "^0.12"
```

**`[build-dependencies]`** - Only needed at build time (e.g., code generation, native compilation):
```toml
[build-dependencies]
cc = "^1.0"
bindgen = "^0.69"
```

Dev and build dependencies use the same syntax as `[dependencies]` (version strings, inline tables, git sources, etc.).

### The Lockfile: `horus.lock`

When you install or resolve dependencies, HORUS generates a `horus.lock` file alongside your `horus.toml`. This lockfile records the exact resolved versions of every dependency (including transitive ones), ensuring **deterministic builds** across machines and CI environments.

- **Commit `horus.lock` to version control** for applications and deployable projects
- For library packages, you may choose to omit `horus.lock` from version control so downstream consumers resolve their own versions
- Run `horus update` to refresh the lockfile when you want to pick up new compatible versions

### Examples

**Minimal:**
```toml
[dependencies]
horus = "*"
```

**With external packages:**
```toml
[dependencies]
horus = "*"
serde = "1"
tokio = "1"
numpy = { version = "*", source = "pypi" }  # Python
```

**With versions and features:**
```toml
[dependencies]
horus = "*"
serde = { version = "1", features = ["derive"] }
tokio = { version = "1", features = ["full"] }
eframe = "0.29"
egui = "0.29"
```

## Ignore Patterns

### `ignore` (Optional)

Exclude files, directories, and packages from HORUS processing.

**Type**: Table with optional `files`, `directories`, `packages` arrays
**Required**: No
**Default**: None

### `ignore.files`

Exclude specific files from detection and execution.

**Type**: Array of glob patterns
**Patterns**: `*` (wildcard), `**/` (recursive directories)

**Examples:**
```toml
[ignore]
files = [
  "debug_*.py",          # Ignore debug_test.py, debug_node.py
  "test_*.rs",           # Ignore all test files
  "**/experiments/**",   # Ignore files in any experiments/ directory
  "scratch.rs",          # Ignore specific file
]
```

### `ignore.directories`

Exclude entire directories.

**Type**: Array of directory names or paths

**Examples:**
```toml
[ignore]
directories = ["old/", "experiments/", "tests/", "benchmarks/"]
```

### `ignore.packages`

Prevent auto-installation of specific packages.

**Type**: Array of package names

**Examples:**
```toml
[ignore]
packages = [
  "ipython",   # Development shell
  "jupyter",   # Notebook environment
  "pytest",    # Testing framework
]
```

**Use Case**: Development-only packages that shouldn't be auto-installed in production.

### Complete Ignore Example

```toml
[package]
name = "robot_controller"
version = "0.1.0"

[dependencies]
horus = "*"
serde = "1"

[ignore]
# Don't run debug files
files = ["debug_*.py", "test_*.rs", "**/temp/**"]

# Don't process these directories
directories = ["old_controllers/", "experiments/", "docs/"]

# Don't auto-install these packages
packages = ["ipython", "jupyter", "black"]  # black = code formatter
```

**See Also**: [Environment Management - Ignoring Files](/package-management/environment-management#ignoring-files-and-packages)

## The `.horus/` Directory

The `.horus/` directory is **automatically managed** by HORUS. You should never manually edit files inside it.

### Structure

```
my_project/
├── horus.toml              # Your configuration (edit this)
├── horus.lock              # Dependency lockfile (commit this)
├── main.rs                 # Your code (edit this)
└── .horus/                 # Auto-managed (don't touch)
    ├── packages/           # Symlinks to global cache
    │   ├── horus -> ~/.horus/cache/horus@0.1.0/
    │   └── serde -> ~/.horus/cache/serde@1.0.228/
    ├── Cargo.toml          # Generated for Rust projects
    ├── Cargo.lock          # Cargo lock file
    └── target/             # Rust build artifacts
```

### Global Cache vs Local Workspace

**Global Cache** (`~/.horus/cache/`):
- Shared across all projects
- Downloaded once, used everywhere
- Saves disk space

**Local Workspace** (`.horus/`):
- Project-specific symlinks
- Isolated from other projects
- Auto-generated on `horus run`

### What's Inside `.horus/`

**`packages/`**:
- Symlinks to global cache packages
- Some packages may be installed directly (no symlink)

**`Cargo.toml`** (Rust projects):
- Auto-generated from `horus.toml` dependencies
- Uses path-based dependencies (no source copying)
- Never edit manually (regenerated on each run)

**`Cargo.lock`** (Rust projects):
- Cargo's dependency lock file
- Auto-managed

**`target/`** (Rust projects):
- Cargo build artifacts
- Can be large (ignore in git)

**`bin/`, `lib/`, `include/`**:
- Compiled binaries and libraries
- Auto-created as needed

### Git Configuration

**Always add to `.gitignore`:**
```gitignore
# Auto-managed HORUS environment
.horus/

# Keep configuration and lockfile
!horus.toml
!horus.lock
```

The `horus new` command automatically creates this `.gitignore` for you.

### When `.horus/` is Created

`.horus/` is created automatically when you run:
- `horus run`
- `horus install`
- `horus env restore`

You never need to create it manually.

### Cleaning `.horus/`

**Remove local environment:**
```bash
rm -rf .horus/
```

**Regenerate on next run:**
```bash
horus run  # Automatically recreates .horus/
```

**See Also**: [Environment Management](/package-management/environment-management#understanding-horus-s-hidden-environment)

## Best Practices

### Version Your Configuration

Always commit `horus.toml` and `horus.lock` to version control:
```bash
git add horus.toml horus.lock
git commit -m "Update dependencies: add sensor-fusion package"
```

### Use Semantic Versioning

Follow semver for your project version:
- `0.x.y` - Initial development
- `1.0.0` - First stable release
- `x.y.z` - Major.Minor.Patch

### Pin Critical Dependencies

For production, consider pinning exact versions:
```toml
[dependencies]
critical-package = "=1.2.3"  # Exact version
```

### Document Your Configuration

Add comments to explain non-obvious choices:
```toml
[dependencies]
# Version 2.0 required for new path planning algorithm
motion-planner = "^2.0"
```

### Keep It Minimal

Only specify what you need:
```toml
# Good (minimal)
[package]
name = "my_robot"
version = "0.1.0"

[dependencies]
horus = "*"

# Overkill for simple projects
# [package]
# name = "my_robot"
# version = "0.1.0"
# description = "A robot"
# author = "Me"
# license = "MIT"
# mode = "debug"
# language = "rust"
```

## Validation

HORUS validates `horus.toml` on every command. Common errors:

### Missing Required Fields

```
Error: Missing required field 'name' in horus.toml
```

**Fix**: Add `name` and `version` fields under `[package]`.

### Invalid TOML Syntax

```
Error: Failed to parse horus.toml: invalid TOML syntax at line 5
```

**Fix**: Check TOML syntax (key-value pairs use `=`, strings must be quoted, tables use `[brackets]`).

### Invalid Version Format

```
Error: Invalid version format: '1.0'. Expected semantic version (e.g., '1.0.0')
```

**Fix**: Use format `"MAJOR.MINOR.PATCH"`.

## Migration Guide

### From Cargo Projects

**Before (Cargo.toml):**
```toml
[package]
name = "my-robot"
version = "0.1.6"
edition = "2021"

[dependencies]
serde = { version = "1", features = ["derive"] }
tokio = { version = "1", features = ["full"] }
```

**After (horus.toml):**
```toml
[package]
name = "my-robot"
version = "0.1.0"

[dependencies]
horus = "*"
serde = { version = "1", features = ["derive"] }
tokio = { version = "1", features = ["full"] }
```

**Then run:**
```bash
horus run  # HORUS generates Cargo.toml automatically
```

### From Python Projects

**Before (requirements.txt):**
```
numpy==1.24.0
opencv-python>=4.5
pillow
```

**After (horus.toml):**
```toml
[package]
name = "vision-processor"
version = "0.1.0"
language = "python"

[dependencies]
horus_py = "*"
numpy = { version = "1.24.0", source = "pypi" }
opencv-python = { version = ">=4.5", source = "pypi" }
pillow = { version = "*", source = "pypi" }
```

### From horus.yaml (Legacy)

If you are migrating from the legacy `horus.yaml` format:

1. Create a new `horus.toml` file
2. Move metadata fields (`name`, `version`, `description`, etc.) under a `[package]` table
3. Convert dependencies from YAML list syntax to TOML table syntax:
   - `- horus` becomes `horus = "*"` under `[dependencies]`
   - Object deps like `name: serde` / `version: "1"` / `features: [derive]` become `serde = { version = "1", features = ["derive"] }`
4. Convert `ignore:` block to `[ignore]` table with arrays
5. Delete the old `horus.yaml`

**Before (horus.yaml):**
```yaml
name: my-robot
version: "0.1.0"

dependencies:
  - horus
  - name: serde
    version: "1"
    features:
      - derive

ignore:
  files:
    - "debug_*.rs"
```

**After (horus.toml):**
```toml
[package]
name = "my-robot"
version = "0.1.0"

[dependencies]
horus = "*"
serde = { version = "1", features = ["derive"] }

[ignore]
files = ["debug_*.rs"]
```
