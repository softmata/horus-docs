# Plugins

HORUS has two plugin systems that extend its functionality:

- **CLI Plugins** add new subcommands to the `horus` CLI (e.g., `horus sim3d`, `horus tensorrt`)
- **Driver Plugins** provide runtime-loadable hardware drivers (e.g., IMU, LIDAR, camera backends)

## CLI Plugins

CLI plugins are standalone binaries that integrate with the `horus` command. When you run `horus sim3d`, HORUS discovers and executes the `sim3d` plugin binary, passing through all arguments.

**How it works:**

1. Any package named `horus-*` with a binary is automatically a plugin
2. Installing it registers the binary with the HORUS plugin system
3. Running `horus <command>` checks plugins before showing "unknown command"

```bash
# Install a plugin
horus plugins install horus-sim3d

# Use it as a native command
horus sim3d --robot kuka_iiwa

# List installed plugins
horus plugin list
```

**Plugin resolution order:**

| Priority | Location | Scope |
|----------|----------|-------|
| 1st | `.horus/plugins.lock` (project) | Local project only |
| 2nd | `~/.horus/plugins.lock` (global) | All projects |
| 3rd | `PATH` lookup for `horus-*` binaries | System-wide |

Project plugins override global ones, so you can pin a specific version per project.

## Driver Plugins

Driver plugins implement the `DriverPlugin` trait and provide hardware abstraction. They can be loaded statically (compiled in) or dynamically (`.so` files loaded at runtime).

```rust
use horus_core::plugin::{DriverPlugin, PluginManifest, ProbeResult, PluginHealth};

pub struct MyImuPlugin;

impl DriverPlugin for MyImuPlugin {
    fn manifest(&self) -> PluginManifest { /* ... */ }
    fn probe(&self, backend_id: &str) -> Vec<ProbeResult> { /* ... */ }
    fn create(&self, backend_id: &str, config: &SingleDriverConfig)
        -> HorusResult<Box<dyn Any + Send + Sync>> { /* ... */ }
    fn health(&self) -> PluginHealth { /* ... */ }
}
```

Driver plugins support:

- **Hardware auto-detection** via `probe()` scanning
- **Multiple backends** per plugin (e.g., MPU6050 + BNO055 in one IMU plugin)
- **Hot-reloading** for development without restarting
- **Health monitoring** for runtime diagnostics

## Comparison

| Feature | CLI Plugin | Driver Plugin |
|---------|-----------|---------------|
| **Purpose** | Add CLI commands | Provide hardware drivers |
| **Language** | Any (binary) | Rust |
| **Loading** | Subprocess | In-process (static or dynamic) |
| **Discovery** | `plugins.lock` + PATH | `PluginLoader` scan |
| **Hot-reload** | N/A | Optional (`HotReloadable` trait) |
| **Examples** | `horus-sim3d`, `horus-tensorrt` | IMU drivers, camera backends |
