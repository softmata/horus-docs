# Managing Plugins

HORUS provides CLI commands for managing both CLI plugins and driver plugins throughout their lifecycle.

## Installing Plugins

Plugins are installed through the `horus plugins install` command. They default to **global** installation since they extend the CLI tool itself.

```bash
# Install a plugin globally (default)
horus plugins install horus-sim3d

# Install a specific version
horus plugins install horus-sim3d -v 1.2.0

# Install locally to current project only
horus plugins install horus-sim3d --local
```

**What happens during installation:**

1. Downloads the package from the registry (or builds from crates.io)
2. Detects plugin metadata (from `horus.yaml`, `Cargo.toml`, or naming convention)
3. Registers the plugin binary in `plugins.lock`
4. Creates symlinks in the bin directory
5. Updates `horus.yaml` dependencies (for local installs)

**Output example:**

```
[PLUGIN] Installing plugin: horus-sim3d
  Scope: global (~/.horus/cache/)

  Downloading horus-sim3d@1.0.0...
  Extracted to ~/.horus/cache/horus-sim3d@1.0.0/

  Registered CLI command: horus sim3d

Plugin horus-sim3d v1.0.0 installed successfully!
```

### Global vs Local Installation

| Aspect | Global | Local |
|--------|--------|-------|
| **Location** | `~/.horus/cache/` | `.horus/packages/` |
| **Scope** | All projects | Current project only |
| **Lock file** | `~/.horus/plugins.lock` | `.horus/plugins.lock` |
| **Default for plugins** | Yes | No (use `--local`) |
| **Override behavior** | &mdash; | Overrides global |

Local plugins always take priority over global plugins with the same command name. This lets you pin a specific plugin version for a project without affecting other projects.

## Listing Plugins

```bash
# List installed plugins
horus plugin list
```

**Output:**

```
INSTALLED PLUGINS:
    sim3d    HORUS 3D simulator  (global)
    tensorrt TensorRT inference  (project)
```

## Removing Plugins

```bash
# Remove a plugin
horus plugins remove horus-sim3d

# Remove from global scope explicitly
horus plugins remove horus-sim3d --global
```

HORUS automatically detects whether the plugin is installed globally or locally. The removal process:

1. Unregisters the CLI command from `plugins.lock`
2. Removes the symlink from the bin directory
3. Deletes the package files

## Enabling and Disabling Plugins

You can temporarily disable a plugin without uninstalling it:

```bash
# Disable a plugin
horus plugin disable sim3d

# Re-enable it
horus plugin enable sim3d
```

Disabled plugins remain installed but HORUS will not execute them. Running a disabled plugin produces an error:

```
Plugin 'sim3d' is disabled. Run 'horus pkg enable sim3d' to re-enable.
```

## Verifying Plugin Integrity

HORUS records SHA-256 checksums when plugins are installed. Verify that no binaries have been tampered with:

```bash
horus plugin verify
```

**Output (healthy):**

```
Verifying installed plugins...
  sim3d     (horus-sim3d v1.0.0) ... OK
  tensorrt  (horus-tensorrt v2.1.0) ... OK

All plugins verified.
```

**Output (tampered):**

```
Verifying installed plugins...
  sim3d     (horus-sim3d v1.0.0) ... FAILED
    Expected: sha256:abc123...
    Actual:   sha256:def456...

1 plugin(s) failed verification!
Run 'horus plugins install horus-sim3d' to reinstall.
```

## The plugins.lock File

Plugin registrations are stored in `plugins.lock` (JSON format). You typically don't need to edit this file directly, but understanding its structure helps with debugging:

```json
{
  "version": 1,
  "plugins": {
    "sim3d": {
      "package": "horus-sim3d",
      "version": "1.0.0",
      "source": "Registry",
      "binary": "/home/user/.horus/cache/horus-sim3d@1.0.0/bin/sim3d",
      "checksum": "sha256:abc123...",
      "installed_at": "2025-10-15T10:30:00Z",
      "installed_by": "0.1.7",
      "compatibility": {
        "horus_min": "0.1.0",
        "horus_max": "1.0.0"
      },
      "commands": [
        {
          "name": "sim3d",
          "description": "HORUS 3D robot simulator"
        }
      ],
      "permissions": []
    }
  },
  "disabled": []
}
```

**File locations:**

- Global: `~/.horus/plugins.lock`
- Project: `.horus/plugins.lock`

## Using Plugins via `horus add`

The `horus add` command provides smart detection. It automatically recognizes plugins:

```bash
# Auto-detects as a plugin and installs globally
horus add horus-sim3d

# Force install as plugin (if auto-detection fails)
horus add my-tool --plugin
```

## Troubleshooting

### Plugin Not Found

```
error: no such command: `mycommand`
```

**Solutions:**

```bash
# Check if plugin is installed
horus plugin list

# Reinstall
horus plugins install horus-mycommand

# Check if binary exists in PATH
which horus-mycommand
```

### Checksum Mismatch

```
Plugin 'mycommand' checksum mismatch!
```

The binary was modified after installation. Reinstall:

```bash
horus plugins install horus-mycommand
```

### Compatibility Warning

```
[WARN] Plugin 'mycommand' v1.0.0 may not be compatible with HORUS v0.2.0
       Requires: 0.1.0 <= horus < 0.2.0
```

The plugin was built for an older HORUS version. It may still work, but consider upgrading:

```bash
horus plugins install horus-mycommand -v 2.0.0
```

### Plugin Binary Not Found

```
Plugin binary not found: /home/user/.horus/cache/horus-mycommand@1.0.0/bin/mycommand
```

The package is registered but the binary is missing. Reinstall:

```bash
horus plugins remove horus-mycommand
horus plugins install horus-mycommand
```
