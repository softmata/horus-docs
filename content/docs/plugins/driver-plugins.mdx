# Driver Plugins

<Callout type="warn" title="Planned Feature">

Runtime-loadable driver plugins are **planned but not yet implemented**. The types described below (`DriverPlugin` trait, `PluginLoader`, dynamic `.so` loading) do not exist in the current codebase. Hardware drivers are currently implemented as regular HORUS nodes.

</Callout>

## Current Approach: Driver Nodes

Today, hardware drivers in HORUS are implemented as regular nodes that publish/subscribe to topics:

```rust,ignore
use horus::prelude::*;

struct ImuNode {
    // I2C or serial connection to hardware
}

impl Node for ImuNode {
    fn name(&self) -> &str { "imu" }

    fn tick(&mut self) {
        // Read from hardware
        // Publish to topic via scheduler context
    }
}

let mut scheduler = Scheduler::new();
scheduler.add(ImuNode { /* ... */ }).order(0).done();
scheduler.run()?;
```

## Planned: Plugin-Based Drivers

A future driver plugin system would enable:

- **Hardware auto-detection** — Scan I2C/SPI/USB buses for known devices
- **Runtime loading** — Load `.so` driver libraries without recompilation
- **Hot-reloading** — Replace drivers during development without restarting
- **Plugin marketplace** — Install drivers from the registry (`horus install --plugin horus-rplidar`)

## Available Hardware Plugins (via Registry)

The following hardware plugins are planned for the HORUS registry:

| Plugin | Category | Hardware |
|--------|----------|----------|
| `horus-rplidar` | LiDAR | Slamtec RPLiDAR (A1, A2, A3, S1, S2) |
| `horus-velodyne` | LiDAR | Velodyne (VLP-16, VLP-32, HDL-32E, HDL-64E) |
| `horus-odrive` | Motor | ODrive (v3.x, S1, Pro) |

Search for available plugins:

```bash
horus search camera
horus search
```
