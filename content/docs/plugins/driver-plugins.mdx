# Driver Plugins

Driver plugins provide hardware abstraction for HORUS. They implement the `DriverPlugin` trait from `horus_core` and can be loaded statically (compiled into your binary) or dynamically (`.so` files loaded at runtime).

## The DriverPlugin Trait

Every driver plugin implements four required methods:

```rust
use horus_core::plugin::{DriverPlugin, PluginManifest, ProbeResult, PluginHealth};
use horus_core::driver::SingleDriverConfig;
use horus_core::error::HorusResult;
use std::any::Any;

pub struct MyPlugin;

impl DriverPlugin for MyPlugin {
    /// Describe the plugin and its backends
    fn manifest(&self) -> PluginManifest { /* ... */ }

    /// Scan for hardware this plugin can drive
    fn probe(&self, backend_id: &str) -> Vec<ProbeResult> { /* ... */ }

    /// Create a driver instance for a specific backend
    fn create(&self, backend_id: &str, config: &SingleDriverConfig)
        -> HorusResult<Box<dyn Any + Send + Sync>> { /* ... */ }

    /// Report plugin health status
    fn health(&self) -> PluginHealth { /* ... */ }
}
```

There are also two optional lifecycle methods:

- `on_load()` &mdash; Called when the plugin is loaded (check dependencies, initialize state)
- `on_unload()` &mdash; Called when the plugin is unloaded (cleanup resources)

## Complete Example: IMU Driver Plugin

This example creates a plugin that supports two IMU backends (MPU6050 and BNO055):

```rust
use horus_core::plugin::{
    DriverPlugin, PluginManifest, ProbeResult, PluginHealth, BackendInfo,
};
use horus_core::driver::{DriverCategory, SingleDriverConfig};
use horus_core::error::{HorusError, HorusResult};
use std::any::Any;
use std::collections::HashMap;

pub struct ImuPlugin;

impl DriverPlugin for ImuPlugin {
    fn manifest(&self) -> PluginManifest {
        PluginManifest {
            id: "horus-imu".into(),
            name: "HORUS IMU Driver".into(),
            version: "1.0.0".into(),
            category: DriverCategory::Sensor,
            description: "IMU drivers for MPU6050 and BNO055".into(),
            author: Some("Your Name".into()),
            license: Some("MIT".into()),
            repository: Some("https://github.com/you/horus-imu".into()),
            backends: vec![
                BackendInfo {
                    id: "mpu6050".into(),
                    name: "MPU6050".into(),
                    description: "InvenSense MPU-6050 6-axis IMU".into(),
                    hardware_ids: vec!["i2c:0x68".into(), "i2c:0x69".into()],
                },
                BackendInfo {
                    id: "bno055".into(),
                    name: "BNO055".into(),
                    description: "Bosch BNO055 9-axis IMU with fusion".into(),
                    hardware_ids: vec!["i2c:0x28".into(), "i2c:0x29".into()],
                },
            ],
            system_deps: vec!["libi2c-dev".into()],
            horus_version: ">=0.1.0".into(),
            platforms: vec!["linux".into()],
            features: vec!["calibration".into(), "fusion".into()],
            extra: HashMap::new(),
        }
    }

    fn probe(&self, backend_id: &str) -> Vec<ProbeResult> {
        let mut results = Vec::new();

        if backend_id.is_empty() || backend_id == "mpu6050" {
            // Scan I2C bus for MPU6050 at address 0x68
            if check_i2c_device(0x68) {
                results.push(ProbeResult::detected("mpu6050", "/dev/i2c-1:0x68"));
            } else {
                results.push(ProbeResult::not_detected("mpu6050"));
            }
        }

        if backend_id.is_empty() || backend_id == "bno055" {
            if check_i2c_device(0x28) {
                results.push(ProbeResult::detected("bno055", "/dev/i2c-1:0x28"));
            } else {
                results.push(ProbeResult::not_detected("bno055"));
            }
        }

        results
    }

    fn create(
        &self,
        backend_id: &str,
        config: &SingleDriverConfig,
    ) -> HorusResult<Box<dyn Any + Send + Sync>> {
        match backend_id {
            "mpu6050" => {
                let driver = Mpu6050Driver::new(config)?;
                Ok(Box::new(driver))
            }
            "bno055" => {
                let driver = Bno055Driver::new(config)?;
                Ok(Box::new(driver))
            }
            _ => Err(HorusError::driver(
                format!("Unknown IMU backend: {}", backend_id)
            )),
        }
    }

    fn health(&self) -> PluginHealth {
        PluginHealth::healthy("horus-imu")
    }
}
```

## Static Loading

Static plugins are compiled directly into your binary. Register them at startup:

```rust
use horus_core::plugin::PluginLoader;

fn main() -> HorusResult<()> {
    let mut loader = PluginLoader::new();

    // Register plugins at compile time
    loader.register_static(Box::new(ImuPlugin));
    loader.register_static(Box::new(CameraPlugin));

    // Probe a specific plugin's backends
    let imu_plugin = ImuPlugin;
    let results = imu_plugin.probe("mpu6050");
    for result in &results {
        println!("{}: detected={}", result.backend_id, result.detected);
    }

    // Create a driver from a specific backend
    let config = SingleDriverConfig::default();
    let driver = imu_plugin.create("mpu6050", &config)?;

    Ok(())
}
```

**When to use static loading:**

- Embedded systems with fixed hardware
- Maximum performance (zero dynamic dispatch overhead)
- Deployment where `.so` management is impractical

## Dynamic Loading

Dynamic plugins are compiled as shared libraries (`.so`) and discovered at runtime:

### Step 1: Create a `cdylib` Crate

```toml
[lib]
crate-type = ["cdylib"]
```

### Step 2: Export the Entry Point

```rust
// Must be the exact symbol name HORUS looks for
#[no_mangle]
pub extern "C" fn horus_driver_entry() -> Box<dyn DriverPlugin> {
    Box::new(ImuPlugin)
}
```

### Step 3: Build the Shared Library

```bash
cargo build --release
# Produces: target/release/libhorus_imu.so
```

### Step 4: Install the Plugin

Place the `.so` file where HORUS can find it:

```bash
# Global plugin directory
mkdir -p ~/.horus/plugins/
cp target/release/libhorus_imu.so ~/.horus/plugins/

# Or project-local
mkdir -p .horus/plugins/
cp target/release/libhorus_imu.so .horus/plugins/
```

HORUS scans these directories and loads any `.so` files with the `horus_driver_entry` symbol.

**When to use dynamic loading:**

- Multiple hardware configurations across deployments
- Hot-reloading during development
- Plugin marketplaces where users install drivers independently

## The DriverLoader

`DriverLoader` wraps `PluginLoader` and adds mode configuration:

```rust
use horus_core::plugin::DriverLoader;
use horus_core::plugin::DriverMode;

// Static only - no dynamic loading
let loader = DriverLoader::new(DriverMode::Static);

// Dynamic only - scan plugin directories
let loader = DriverLoader::new(DriverMode::Dynamic);

// Hybrid - static plugins first, then scan for dynamic
let loader = DriverLoader::new(DriverMode::Hybrid);
```

In hybrid mode, static plugins take priority. If a backend is provided by both a static and dynamic plugin, the static version is used.

## Auto-Detection

All `DriverPlugin` implementations automatically get the `AutoDetectable` trait. This probes all backends and creates a driver using the first detected hardware with the highest confidence:

```rust
let config = SingleDriverConfig::default();

// Automatically probes mpu6050 and bno055, picks the best match
let driver = imu_plugin.auto_create(&config)?;
```

## Hot-Reloading

For development, implement the optional `HotReloadable` trait:

```rust
use horus_core::plugin::HotReloadable;

impl HotReloadable for ImuPlugin {
    fn can_hot_reload(&self) -> bool {
        // Check if any active driver instances would be invalidated
        true
    }

    fn prepare_hot_reload(&self) -> HorusResult<()> {
        // Save state before unloading
        Ok(())
    }

    fn complete_hot_reload(&self) -> HorusResult<()> {
        // Restore state after reloading
        Ok(())
    }
}
```

This lets you recompile and reload a driver `.so` without restarting the entire system.

## Plugin Manifest Fields

| Field | Type | Description |
|-------|------|-------------|
| `id` | `String` | Unique plugin identifier (e.g., `"horus-imu"`) |
| `name` | `String` | Human-readable name |
| `version` | `String` | Semver version |
| `category` | `DriverCategory` | `Sensor`, `Actuator`, `Bus`, `Input`, `Simulation` |
| `description` | `String` | What the plugin does |
| `backends` | `Vec<BackendInfo>` | Hardware backends provided |
| `system_deps` | `Vec<String>` | System packages required (e.g., `libi2c-dev`) |
| `horus_version` | `String` | Compatible HORUS version range |
| `platforms` | `Vec<String>` | Supported platforms (`linux`, `macos`, etc.) |
